# 功能规格：媒体资产后台管理能力

**特性分支**：`001-docs-media-storage`  
**创建日期**：2025-10-07  
**状态**：草稿  
**输入来源**：用户描述：“参考 docs/media_storage_design.md docs/media_storage_admin_api.md”

## 用户场景与测试（必填）

### 主要用户故事

作为后台运营或内容管理人员，我希望在同一个后台中上传、查找、更新和下架媒体资产，并为业务部门生成临时访问链接，从而高效管理图片、视频等资源。

### 验收场景

1. **Given** 管理员拥有后台访问权限且存储驱动已配置，**When** 管理员通过后台选择文件或填写外部文件链接发起上传，**Then** 系统应校验请求、保存媒体元数据并返回可访问的资源信息。
2. **Given** 管理员需要定位历史素材，**When** 管理员在媒体列表中按关键字、存储驱动或归属主体筛选，**Then** 系统应返回对应的分页结果及总数，并允许进入详情查看完整信息。

### 边界情况

- 当上传请求未附带文件且没有有效的外部链接时，系统应提示缺少可用资源并拒绝创建媒体资产。
- 当管理员尝试访问已被软删除或禁用的资源时，系统应阻止访问并给出资源不可用的提示。

## 需求（必填）

### 功能性需求

- **FR-001**：允许具有后台权限的人员创建媒体资产，支持上传本地文件或引用可信外部链接；记录名称、驱动、目录、归属主体与可选标签等元数据。
- **FR-002**：校验所选存储驱动处于启用状态；若配置缺失或被停用则拒绝操作并返回明确原因。
- **FR-003**：提供媒体资产分页列表，支持按关键字、驱动类型、归属主体（类型与 ID）及可选标签筛选，并展示满足条件的总记录数。
- **FR-004**：提供媒体资产详情视图，包含基础元数据、创建/更新时间、业务状态以及依驱动生成的访问地址（如临时 URL 的到期信息）。
- **FR-005**：允许管理员更新业务属性（名称、描述、标签、业务状态等），更新不得改变底层存储位置或驱动配置。
- **FR-006**：支持软删除媒体资产，并在删除时记录操作人和时间；若策略要求同步物理删除，应在完成底层文件清理后反馈结果。
- **FR-007**：能够为指定媒体资产或即将上传的资源生成带有效期的预签名链接，过期后自动失效，并确保仅授权管理员可生成。
- **FR-008**：对上传、更新、删除与预签名操作留下可审计记录，以便追溯操作来源、操作人及相关参数。

### 关键实体

- **媒体资产**：平台管理的单个文件或外部资源，包含名称、存储驱动、访问地址、文件大小、归属主体、标签、业务状态、创建与更新时间，以及软删除标记。
- **媒体存储驱动**：系统可用的存储选项（本地文件系统或兼容 S3 的对象存储），包含驱动标识、可用状态、基础访问路径与预签名配置。
- **预签名访问请求**：为上传或下载生成的临时访问授权，包含目标资产标识、链接类型（上传/下载）、有效期、允许的 HTTP 方法以及需要返回给前端的附加字段。

## 前置假设与依赖

- 系统已具备后台身份验证与授权能力，可识别操作者身份并限定接口访问人群。
- 存储驱动的基础配置（桶、访问密钥、基础 URL 等）由运维或配置中心事先维护，媒体管理模块基于这些配置提供服务。
- 业务方已有统一的标签与归属主体编码标准，创建或更新媒体资产时需遵守该标准。
