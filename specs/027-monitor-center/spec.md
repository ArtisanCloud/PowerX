## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置并启用自动备份策略 (Priority: P1)

作为 Root 管理员，我可以在系统中设置自动备份计划（频率、保留数量、目标库/实例），并启用后由系统自动执行，无需人工每天手动触发。

**Independent Test**: 管理员可完成策略配置并观察到至少一次计划内备份成功执行。

### User Story 2 - 监控备份任务状态与历史 (Priority: P1)

作为 Root 管理员，我可以在监控入口中查看自动备份任务的当前状态、最近执行历史和关键统计，从而快速判断备份是否健康。

**Independent Test**: 管理员能在统一页面看到“计划任务 + 执行历史 + 成功失败状态”。

### User Story 3 - 快速演练恢复可用性 (Priority: P2)

作为 Root 管理员，我可以从指定备份记录触发一次恢复任务（不影响正式业务数据），并看到执行结论，以验证备份可用而非“仅有文件”。

**Independent Test**: 基于既有备份记录可发起恢复任务并拿到成功/失败结论。

### User Story 4 - 日志与链路追踪监控 (Priority: P1)

作为 Root 管理员，我可以在监控中心的日志页面按 trace/job/policy 查询日志，并根据当前日志驱动（loki/file/stdio）获得对应能力展示与跳转，从而快速定位备份与恢复问题。

**Why this priority**: 备份闭环已经可执行，但没有统一日志检索与链路关联会导致排障成本高。  
**Independent Test**: 不依赖恢复流程，仅通过日志页即可检索最近一次备份/恢复任务并定位关键错误。

**Acceptance Scenarios**:

1. **Given** 系统日志驱动为 `loki`，**When** 管理员进入日志页，**Then** 可按 trace_id/policy_id/job_id 检索并获得 Grafana 深链。
2. **Given** 系统日志驱动为 `file`，**When** 管理员检索日志，**Then** 返回本地日志内容并提示“不可用能力”（如无标签聚合）。
3. **Given** 系统日志驱动为 `stdio`，**When** 管理员检索日志，**Then** 返回 ring buffer 最近窗口数据并提示历史窗口受限。

---

### Edge Cases

- 自动备份执行时间到达时，上一轮备份仍在运行，系统如何避免重复执行和资源冲突。
- 存储空间不足导致备份中断时，系统如何标记失败并提示管理员介入。
- 保留策略触发清理时，若删除旧备份失败，系统如何保证新备份记录不丢失且告警可见。
- 时区变更或夏令时切换导致计划触发偏移时，系统如何保持预期执行节奏。
- 恢复任务目标环境不可用时，系统如何给出明确失败结论并防止误判为“备份可用”。
- 日志驱动从 `loki` 切换为 `file/stdio` 后，监控页如何降级展示并避免用户误解。
- `trace_id` 缺失或跨服务未透传时，日志页如何回退到 `policy_id/job_id/time-range` 检索。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持 Root 管理员创建、编辑、启用、停用自动备份策略。
- **FR-002**: 系统 MUST 对备份策略进行输入校验，并在非法输入时阻止保存。
- **FR-003**: 系统 MUST 按已启用策略自动触发备份作业，并记录每次作业的开始时间、结束时间、执行状态。
- **FR-004**: 系统 MUST 为每次备份作业生成唯一作业记录，确保可追踪到对应策略与租户上下文。
- **FR-005**: 系统 MUST 提供备份作业历史查询能力，支持按状态、时间范围、任务标识筛选。
- **FR-006**: 系统 MUST 在监控入口展示自动备份任务的当前状态、下次执行时间、最近执行结果与失败摘要。
- **FR-007**: 系统 MUST 在备份失败时生成可见告警信息，包含可操作的排查提示。
- **FR-008**: 系统 MUST 支持从备份记录触发恢复任务，并可查看执行进度与最终结论。
- **FR-009**: 系统 MUST 在自动备份与恢复操作中保留完整审计轨迹（操作者、时间、动作、结果）。
- **FR-010**: 系统 MUST 支持保留策略，能够在不破坏最新可用备份的前提下清理过期备份产物。
- **FR-011**: 系统 MUST 提供默认自动备份频率基线为每 6 小时一次，并允许 Root 管理员按策略覆盖。
- **FR-012**: 系统 MUST 提供默认保留策略为最近 14 份备份产物，并允许 Root 管理员按策略覆盖。
- **FR-013**: 系统 MUST 提供默认恢复任务节奏为每周一次，并允许 Root 管理员按策略覆盖或临时手动触发。
- **FR-014**: 系统 MUST 在备份连续 2 次失败时自动升级为高优先级告警，并在监控入口突出展示。
- **FR-015**: 系统 MUST 以 Asia/Shanghai 作为默认调度时区，并允许 Root 管理员按策略覆盖时区配置。
- **FR-016**: 系统 MUST 提供日志配置查询接口，返回当前驱动类型（`loki/file/stdio`）与能力矩阵。
- **FR-017**: 系统 MUST 提供统一日志查询接口，至少支持 `trace_id/job_id/policy_id/time_range/keyword` 过滤。
- **FR-018**: 系统 MUST 在 `loki` 驱动下支持标签检索与 Grafana 深链（可按 trace/job 跳转）。
- **FR-019**: 系统 MUST 在 `file` 驱动下支持基于文件的时间窗口检索，并明确不可用能力。
- **FR-020**: 系统 MUST 在 `stdio` 驱动下支持最近窗口（ring buffer）检索，并提示历史窗口限制。
- **FR-021**: 监控中心 Logs/Trace 页面 MUST 根据驱动能力动态渲染，不得展示不可用操作入口。
- **FR-022**: 日志查询与跳转能力 MUST 仅对 Root 管理员开放，并记录审计日志。
- **FR-023**: 当日志驱动不可用或查询失败时，系统 MUST 返回可操作错误提示（驱动状态、建议步骤、trace_id）。
- **FR-024**: 系统 MUST 提供统一日志保留策略入口 `log.retention`，覆盖文件日志与数据库日志清理策略（按来源可配置 retention 与执行计划），避免仅依赖 rotate 导致总量不可控。
- **FR-025**: 系统 MUST 提供日志保留任务执行记录与审计信息（执行时间、清理来源、删除数量、状态、失败原因），供监控中心查询与告警使用。

### Key Entities *(include if feature involves data)*

- **BackupPolicy（备份策略）**: 描述自动备份规则，包括启停状态、执行频率、保留策略、生效范围。
- **BackupJob（备份作业）**: 一次实际备份执行实例，包含执行窗口、状态、结果摘要、错误信息。
- **BackupArtifact（备份产物）**: 备份作业生成的可恢复数据集合标识，包含可用性状态与过期信息。
- **RestoreJob（恢复任务）**: 基于备份产物执行的恢复任务，包含目标环境、执行进度、任务结论。
- **BackupAlert（备份告警）**: 针对失败、延迟、清理异常等事件的告警记录，用于监控视图聚合展示。
- **MonitorLogConfig（日志配置）**: 当前日志驱动配置与能力矩阵快照。
- **MonitorLogEntry（日志条目）**: 监控页可查询的结构化日志记录，包含时间、级别、模块、trace_id、消息体。

## Assumptions

- 自动备份、恢复任务与日志检索均仅对 Root 管理员开放。
- 备份产物已具备统一命名与存储位置约束，策略层不重复定义底层存储协议。
- 恢复任务默认在隔离环境执行，不直接覆盖生产业务数据。
- 日志驱动由系统配置决定，监控页按运行态能力动态降级。

## Dependencies

- 需要存在可用的备份执行环境与存储目标。
- 需要调度能力稳定运行，以保证计划任务按时触发。
- 需要审计与日志能力可用，以支持失败排查与合规留痕。
- 若驱动为 `loki`，需要 Loki API 与 Grafana 地址配置可用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Root 管理员可在 3 分钟内完成自动备份策略创建并启用。
- **SC-002**: 启用后的自动备份策略在连续 7 天内按计划触发率达到 99% 及以上。
- **SC-003**: 备份失败事件在 1 分钟内可在监控入口被识别并查看失败摘要。
- **SC-004**: 管理员在监控入口定位最近一次备份任务状态的平均时间不超过 30 秒。
- **SC-005**: 任意一次恢复任务在结束后 1 分钟内可查看明确结论（成功/失败）与原因摘要。
- **SC-006**: 日志页在 10 秒内返回最近 15 分钟内的备份链路日志（同城网络条件）。
- **SC-007**: `loki/file/stdio` 三驱动下，监控页均可正确展示可用能力与不可用能力提示，误点击率为 0。
