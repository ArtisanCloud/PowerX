# 插件菜单多语言打包规范

PowerX 的 Admin 侧边栏由宿主动态拼接系统菜单与插件菜单。为确保来自 Next.js、Nuxt.js 等不同前端栈的插件能够提供一致的多语言资源，请在插件打包阶段遵循以下规范。宿主在 `/api/admin/menus` 响应中会自动返回合并后的翻译包，前端无需再逐个请求插件资源。

## Manifest 声明

在 `plugin.yaml` 中为 Admin 前端声明 `frontend.admin.i18n` 区块：

```yaml
frontend:
  admin:
    kind: static
    static_dir: ./web-admin/dist
    i18n:
      dir: ./web-admin/i18n       # 相对于插件根目录
      format: i18next             # 可选：i18next/json/nuxt，默认为 i18next
      default_namespace: menus    # 前端优先加载的命名空间
      namespaces:                 # 可选，显式列出需要暴露的命名空间
        - menus
        - common
      locales:                    # 可选，限定宿主需要读取的语言列表
        - zh-CN
        - en
```

说明：
- `dir` 必填，指向多语言资源目录。
- `format` 用于指示前端解析方式，宿主目前将 `i18next/json/nuxt` 都视为结构化 JSON。若省略则默认为 `i18next`。
- `namespaces`、`locales` 若留空，宿主会自动遍历目录推断。

## 目录结构

`dir` 下应按照 `locale/namespace.ext` 组织文件，常见形式如下：

```
web-admin/
  dist/
    ...
  i18n/
    en/
      menus.json
      common.json
    zh-CN/
      menus.json
      common.json
```

- 推荐使用 UTF-8 编码的 `.json` 文件；也支持 `.yaml/.yml`。
- 文件内容需为对象结构，允许嵌套：

```json
{
  "sidebar": {
    "dashboard": "Dashboard",
    "reports": "Reports"
  }
}
```

Nuxt.js 默认的 `locales/<lang>/<namespace>.json` 布局与上述一致，可直接复用；Next.js (next-i18next) 的 `public/locales/<lang>/<namespace>.json` 也满足该约定，打包时仅需将目录复制到 `frontend/admin/i18n`。

## 菜单标题与 i18n Key

插件菜单项支持声明翻译 Key：

```yaml
frontend:
  admin:
    menus:
      - id: dashboard
        route: /
        slot: core.dashboard
        title: "Dashboard"          # 兜底文案
        title_i18n:
          namespace: menus
          key: sidebar.dashboard
          default: "Dashboard"      # 可选，宿主会优先使用 default
```

- `title` 仍作为兜底展示；若提供 `title_i18n.default`，宿主会在接口中返回该默认值并附上 `namespace/key`。
- 前端可以使用宿主返回的 `i18n` 字段（结构为 `pluginId -> locale -> namespace -> messages`）直接注册到自身的 i18n 实例，无需再次读取插件包。

## 宿主侧行为

- 安装时宿主会校验 `dir` 是否存在，`format` 仅接受 `i18next/json/nuxt`。
- 请求 `GET /api/admin/menus` 时，宿主：
  1. 过滤启用状态的插件；
  2. 读取各插件声明的 i18n 目录，自动合并 JSON/YAML；
  3. 在响应中追加 `i18n` 数组，每项包含 `pluginId/defaultNamespace/namespaces/locales`。
- 若某语言缺失资源，宿主会跳过该文件并在日志中输出告警，但不会影响菜单渲染。

## 打包清单 Checklist

1. 在 `plugin.yaml` 写明 `frontend.admin.i18n`。
2. 将 `public/locales` 或 `locales` 目录复制到 `frontend/admin/i18n`。
3. 确保语言文件命名为 `<namespace>.json`（或 `.yaml`）。
4. 在菜单项使用 `title_i18n` 标记翻译 Key，保持与文件一致。
5. 执行打包脚本时确认目标目录包含多语言文件（可写自动化校验）。

遵循上述规范后，PowerX 会自动托管插件菜单多语言资源，前端仅需一次接口即可获得完整的翻译数据。
