# 营销团队：概念、职责与边界

## 业务目标

把一次营销活动的复盘材料转成可审核的方法论草稿。目标不是自动发布知识，也不是替代业务负责人判断。

## 团队组成

| 团队角色 | 智能体 | 绑定能力 | 职责 |
| --- | --- | --- | --- |
| 团队负责人 | `marketing.director_advisor` | 复盘汇总 | 只能基于三个上游产物输出类型化最终报告。 |
| 检索 | `marketing.content_strategist` | 素材解析 | 将原始材料解析为渠道、素材、观察和约束等可追溯事实。 |
| 执行 | `marketing.campaign_reviewer` | 指标提取 | 计算目标完成率与漏斗指标，明确缺失数据，不能虚构归因。 |
| 复核 | `knowledge.expert_curator` | 方法论提取 | 基于素材解析和指标分析产物，输出事实、待验证假设与行动。 |

每个团队恰有一个负责人；只有负责人可以启动该团队任务。子智能体只能接收负责人明确下发的上下文切片。

## 输出边界

```mermaid
flowchart LR
  M[活动复盘材料] --> C[团队协作]
  C --> D[可审核方法论草稿]
  D --> R{人工审核}
  R -->|通过| W[Workflow 写入知识库]
  R -->|拒绝或补充| M
```

- 团队最终答复只引用本轮材料和三个上游节点结果；没有上游结果时最终汇总明确失败，不得回退为原文摘要。
- 缺少预算、漏斗或目标时，答复必须标记缺口，不得补造数据。
- 当前团队不会自动投放、修改广告、联系客户或发布知识库。

## 统一展示

最终节点必须返回 `powerx.agent.response/v3`。执行型 Skill 缺少或输出不合法的信封会使本轮失败，PowerX 不会把原始 Markdown 伪装为完成结果。Skill 只能提交事实、指标、假设、缺口和行动；Web Admin 统一从这些数据渲染结论、事实、指标、假设、缺口、行动与验收项，业务 Skill 不负责页面格式。

运行失败不会把模型已输出的一段文本当作完成答复展示。页面会明确标为失败，并保留“追踪本轮”入口；部分输出只在 Trace 的技术诊断中保留。
