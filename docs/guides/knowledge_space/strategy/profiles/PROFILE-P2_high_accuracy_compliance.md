# PROFILE-P2：高准确 / 合规优先（证据优先）

> 适合“答错一次就出事故”的知识库：宁可慢一点、保守一点，也要可追溯、可纠错。

## 对应策略模块（来自 rag.md）

- 默认模块集合（见 `docs/guides/knowledge_space/strategy/MAP_scene_bundle_rag_profiles.md`）：`H_fusion`, `O_crag`, `F_rerank`, `L_feedback`
- 场景会叠加模块：合同/价格/监管通常叠加 `A2_time_aware`；合同可能叠加 `D_doc_augmentation`
- 模块定义来源：`docs/plan/AI_engineering/knowledge/rag.md#5.2`

## 你会得到什么

- **强证据**：回答更偏向“只说有证据的部分”，并附引用定位。
- **冲突纠错倾向**：遇到版本/条款冲突时优先提示冲突与来源，而不是合并编造。
- **更严格的护栏**：当证据不足时倾向拒答/提示补充材料。

## 前置依赖（必须/建议）

- 必须：`index.dense` + `index.sparse`
- 强烈建议（按场景）：`index.time_fields`（政策/价格/版本）、`index.structured_fields`（编号/金额/日期/条款号）
- 扫描件/图片：需要 OCR 能力（否则会被阻断或显著降级）

## 什么时候选 P2

- 合同/报价/条款：`SCN-020`
- 促销规则/活动口径：`SCN-120`
- 监管/法规口径：`SCN-130`
- 计费/价格规则：`SCN-140`
- 台账/清单（结构化行）：`SCN-040`
- API/数据字典（事实精确）：`SCN-100/101`

## 什么时候不要选 P2

- 你只想做低成本 demo（先 P0/P1）。
- 你核心问题是“关系/依赖/约束推理”（优先 P3）。

## 验收与测试（必须要过）

- 事实类问题回答必须引用来源；引用缺失视为失败。
- 证据不足时能明确“资料中未找到”并给出补充建议（字段/版本/文件）。
- 与 P1 对比：误答率显著降低（允许吞吐/延迟上升，但要可解释）。
