# PROFILE-P1：通用推荐（企业默认）

> 适合大多数“问答 + 总结 + 可追溯引用”的知识库，是默认起步策略。

## 对应策略模块（来自 rag.md）

- 默认模块集合（见 `docs/guides/knowledge_space/strategy/MAP_scene_bundle_rag_profiles.md`）：`H_fusion`, `F_rerank`, `C_context_enriched`, `L_feedback`
- 场景会叠加模块：例如 SOP/长文会叠加 `J_hier`；对话类会叠加 `E_query_transform`
- 模块定义来源：`docs/plan/AI_engineering/knowledge/rag.md#5.2`

## 你会得到什么

- **更稳的召回**：dense + sparse 的 hybrid 基线（通常比 P0 更抗同义词/关键字/格式差异）。
- **更好的可用性**：适度 rerank / query transform（按场景启用），减少“看起来相关但不对”的片段。
- **成本可控**：强策略会有降级/兜底路径（不同场景成本不同）。

## 前置依赖（必须/建议）

- 必须：`index.dense`
- 强烈建议：`index.sparse`（几乎所有企业知识库都需要）
- 长文/章节强相关建议：`index.hier` + `asset.section_summaries`

## 什么时候选 P1

- SOP/制度/产品说明：需要“步骤/规则/解释”类问答与引用定位。
- 研究报告/项目文档/培训资料：需要“归纳总结 + 回到原文引用”。
- 支持 FAQ/工单对话：需要“同义表达覆盖 + 上下文补齐”。

## 什么时候不要选 P1（或需要升级）

- 明显的“事实精确/合规风险”场景（合同/价格/促销规则/监管口径）：优先用 P2。
- 明显的“关系/依赖/约束”场景（KG/拓扑/依赖链）：优先用 P3。

## 适用场景（映射说明）

- `SCN-010`、`SCN-030`、`SCN-080`
- `SCN-150/160/170/180`（会议纪要/项目/工单/培训）
- `SCN-072`（选型对比）偏解释归纳

## 验收与测试（建议问题集）

- 同一个问题换 3 种说法，仍能命中同一段证据。
- “在哪里写的”能定位到章节/标题（如果启用 hier）。
- 对“总结”类问题能给出要点并引用关键段落（避免只总结不引用）。
