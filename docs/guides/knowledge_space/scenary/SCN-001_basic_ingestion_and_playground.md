# SCN-001：默认策略入库 + Playground 验证（第一条推荐验收场景）

> 目标：用“最小但完整”的路径验证知识空间可用性：创建空间 → 入库（本地上传或远程 URL）→ Playground 检索验证。

## 三者关联（L1/L2/L3）

- L1（场景）：按你要做的业务场景选择（例如 SOP/合同/台账/对话/依赖等）
- L2（建库策略包）：决定“要建哪些索引/启哪些护栏/成本强度”，本场景验收建议从 `P0` 或 `P1` 起步（先跑通链路）
- L3（RAG 主策略）：你希望 **RAG 的主发力方向**（例如 `J_hier` 章节层次、`O_crag` 证据纠错、`K_kg` 图谱约束等）。系统会结合 L1/L2 自动拼装模块组合，并在 UI 中展示“默认启用模块”。
  参考：`docs/guides/knowledge_space/scenary/MAP_scene_bundle_rag_profiles.md`

### 本场景的推荐默认（第一次验收建议按这个选）

> 目标是“最低成本跑通闭环 + 可解释 + 好复用”。

- 如果你只是想先跑通：`L1=SOP/制度/产品说明` + `L2=P0 基础（最小闭环）` + `L3=A Simple RAG`
- 如果你希望马上更贴近企业默认：`L1=SOP/制度/产品说明` + `L2=P1 通用推荐（企业默认）` + `L3=J Hier（章节层次）`

**如何理解 L3（RAG 主策略）**
- L3 不是“全部 RAG 模块列表”，而是“主策略单选”（主导默认分割/锚点倾向）。
- 其它 RAG 模块会在 UI 的“默认启用模块（L3）”里作为组合展示（例如 `H Fusion / F Rerank / C Context Enriched / L Feedback`）。

## 适用范围

- 租户业务侧自助（非 admin 帮别人配 UUID）。
- 先验证“默认策略链路是否通”，再逐步引入更复杂的策略与多源同步。

## 前置条件

1. 后端与 Web Admin 已启动，且能正常登录。
2. 当前租户下至少有一个部门可选（如刚执行过 `make db-refresh`，请先退出并重新登录，避免旧 token/ctx 造成部门/空间列表为空）。
3. 至少存在一个可用空间，或你有权限创建空间。

## 测试数据准备（建议）

- 准备一个 1–5 页的 PDF（制度/FAQ/手册均可），内容包含 3–5 个可提问的关键点。
- 准备 1 个简单问题（query），例如：
  - “XX 的流程是什么？”
  - “报销需要哪些材料？”
  - “密码重置怎么做？”

## 步骤 A：创建空间（只创建容器）

1. 进入「知识空间」→ 点击 **新建空间**
2. 填写空间名称（例如：`HR知识库`）
3. 选择所属部门（下拉选择）
4. 点击 **创建空间**
5. 成功后返回「知识空间总览」

**期望结果**
- 总览页列表能看到新空间（可用搜索框按空间名搜索）。

## 步骤 B：入库（默认策略 / 通用模板）

1. 在「知识空间总览」找到目标空间那一行 → 点击 **入库**
2. 在弹层内选择：
   - 空间：应已自动选中/或手动选择
   - 来源类型：`PDF`（或按实际文件类型）
   - 来源方式：**本地上传**
3. 选择文件后点击 **下一步**
4. 场景（L1）选择：建议先用 `SOP/制度/产品说明`（如果你上传的是合同/台账/SQL，请切换到对应场景）
5. 建库策略包（L2）选择：第一次验收建议 `P0`（最低成本）或 `P1`（企业默认）
6. RAG 主策略（L3）选择：
   - SOP/手册/说明文档：建议 `J Hier`
   - 只想跑通链路：可选 `A Simple RAG`
7. 点击 **下一步** → 在分割策略页确认默认值（可覆盖）→ 在确认页点击 **立即入库**

## 分割策略（Segment Defaults）

> 默认值会随“场景（L1）+ 策略包（L2）”变化；可在入库向导第 3 步覆盖。

- 推荐分段模式：`heading`（按结构：标题/段落；无明显结构时按段落）

| 策略包 | segmentMode | chunkSize | overlap | 说明 |
| --- | --- | ---:| ---:| --- |
| P0 | `heading` | 1000 | 0 | 最小成本跑通链路 |
| P1 | `heading` | 800 | 120 | 通用默认（推荐） |
| P2 | `heading` | 650 | 160 | 更细粒度，利于证据定位 |
| P3 | `heading` | 700 | 180 | 若启用 KG/层次索引，重叠稍高以保上下文 |

**期望结果**
- 弹层关闭，并提示“入库已提交”。
- 不出现 `[intlify] Not found ...` 之类的缺失 key 告警（如出现，说明前端 i18n 未更新到最新）。

## 步骤 C：Playground 验证检索

1. 在「知识空间总览」目标空间那一行 → 点击 **Playground**
2. 输入 query（用“测试数据准备”里的问题）
3. 观察返回结果（候选/耗时/降级原因/引用等）

**期望结果**
- 能返回候选与 trace 信息（即便当前入库管线还是占位，也应有可解释的返回结构）。

## 常见失败与定位

### 1) 401 Unauthorized（空间列表/创建/入库）

- 现象：请求 `POST /api/v1/admin/knowledge-spaces` 或 `POST /api/v1/admin/knowledge-spaces/:id/ingestion-jobs` 返回 401
- 处理：
  - 确认已登录、浏览器里有 `access_token`
  - 如刚 `db-refresh`：退出登录 → 重新登录
  - 确认请求头含 `Authorization` 与 `X-Tenant-UUID`（Web Admin 正常会自动注入）

### 2) 部门为空 / 部门树返回空

- 现象：创建空间页部门下拉为空，或接口返回 `data: null`
- 处理：
  - 刷新页面
  - `db-refresh` 后重新登录
  - 后端排查入口：`docs/guides/knowledge_space/runbook.md`

### 3) 503 “No available OpenAI account”

- 含义：触发了需要模型/Provider 的能力，但没有可用账号/路由命中
- 处理：到「AI 设置」配置 provider/账号，并确认租户路由策略生效
