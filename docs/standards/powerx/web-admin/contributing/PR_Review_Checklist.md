# PR 评审清单

> 帮助评审者快速检查 Pull Request 的质量与风险，涵盖代码、测试、UI、文档与安全等维度。

---

## 1. 基础信息
- [ ] 标题清晰、遵循 Conventional Commit 风格。  
- [ ] 描述包含问题背景、解决方案、用户影响。  
- [ ] 提供截图/录屏（UI 变更）。  
- [ ] 列出相关 Issue/需求编号。

---

## 2. 代码质量
- [ ] 目录、命名符合规范（见 `Coding_Standards_and_ESLint.md`）。  
- [ ] 类型定义完整，无滥用 `any`。  
- [ ] 避免重复代码，可复用的逻辑抽到 composable/工具函数。  
- [ ] ESLint/Prettier 通过（CI 或本地截图）。

---

## 3. 功能和测试
- [ ] 新增或修改逻辑是否有对应单元测试/端到端测试。  
- [ ] 手动验证路径说明（哪些浏览器、环境）。  
- [ ] `scripts/check-refactor.sh` 是否在触及 Agent 关键代码时执行。  
- [ ] 对 Mock / Fixture 变更是否更新文档。

---

## 4. 安全与配置
- [ ] 无敏感信息泄露（Token、密码、证书）。  
- [ ] 对外部输入进行校验和转义。  
- [ ] 环境变量变更已更新 `Env_Variables_Schema.md` 与部署说明。  
- [ ] 认证、权限逻辑未被绕过或影响。  
- [ ] 如涉及 CSP/Headers，确认配置正确。

---

## 5. UI/UX
- [ ] 主题、暗色模式兼容。  
- [ ] 多语言文本使用 `t()`，并更新语言包。  
- [ ] 响应式布局在主要断点可用。  
- [ ] 错误提示符合 `UX_Writing_for_Errors.md` 指南。

---

## 6. 性能与可观测性
- [ ] 大型依赖是否按需加载（参见 `Code_Splitting_and_Hydration.md`）。  
- [ ] 关键操作是否记录日志或 Sentry Span。  
- [ ] 长耗时操作提供 Loading 状态或进度提示。

---

## 7. 文档与发布
- [ ] 文档/README 是否更新。  
- [ ] 发布说明（若需要）是否补充。  
- [ ] 是否包含回滚步骤或影响面说明。

---

## 8. 评审输出
- 如需变更：明确指出问题、建议修复方案，可附链接。  
- 若无法确认：提出问题，等待作者补充信息或后续验证。  
- 评审通过时，确认 CI 全绿且满足合并策略（至少 N 名Reviewer）。
