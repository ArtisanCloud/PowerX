# 路由策略管理（Router Policies UI）

> 路由策略用于在多上游之间分发请求或选择模型，本文定义前端界面交互、字段含义、校验规则与错误展现，作为后续实现的参考。

---

## 1. 场景概览

- **入口建议**：侧边栏「路由策略」，路由 `/router/policies`。  
- **使用角色**：平台 Root 管理员、运维工程师；租户管理员可只读。  
- **目标**：管理多上游权重、偏好（prefer/only）、健康阈值以及故障自动切换策略。

---

## 2. 数据模型

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `policyKey` | 策略 ID（唯一） | `llm-primary` |
| `description` | 描述 | `默认 GPT 路由` |
| `targets` | 目标上游数组 | 覆盖配置见下表 |
| `rules` | 触发条件（可选） | 请求头、租户、标签等 |
| `lastModified` | 最近更新时间 | ISO 字符串 |

### 目标上游 (`targets[]`)

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `upstreamKey` | string | ✓ | 关联上游/模型标识 |
| `weight` | number | ✓ | 0-100，可动态调整 |
| `prefer` | boolean | - | 多个标记优先节点 |
| `only` | boolean | - | 若勾选则单路使用 |
| `health` | object | - | 健康阈值（错误率、延迟） |
| `status` | enum | - | `active` / `standby` / `drain` |

---

## 3. 页面结构

1. **列表页**  
   - 表格展示策略 key、描述、目标数量、最后更新时间、状态。  
   - 支持搜索（按 key/描述）、筛选（状态、标签）。  
   - 行操作：`查看`、`编辑`、`复制`、`删除`（需确认）。  
   - 顶部按钮：`新建策略`、`导入 JSON`。

2. **详情/编辑页**  
   - Tab：`基本信息`、`目标上游`、`规则`、`测试`。  
   - `目标上游` Tab 提供拖拽或滑块调整权重、切换 prefer/only。  
   - `测试` Tab 输入模拟请求参数，展示命中结果与调度日志。

---

## 4. 交互细节

- **权重调整**：使用滑块或数字输入，实时更新总和与百分比展示。总权重允许不等于 100，但应给出提示。  
- **Prefer/Only**：  
  - `prefer`：列表支持多选，调度时优先尝试标记项。  
  - `only`：互斥，仅允许一个目标设为 `only`；勾选后其他目标自动禁用。  
- **健康阈值**：表单包含  
  - 错误率上限（%）  
  - 平均响应时间上限（ms）  
  - 连续错误次数阈值  
  - 触发时的降级策略（切换目标、熔断、告警）。  
- **预览 JSON**：提供折叠面板显示当前策略序列化结果，便于导入导出。

---

## 5. 校验与错误处理

- `policyKey`：仅允许小写字母、数字、中划线，长度 3-50。重复时提示“已存在”。  
- 至少一个目标 `weight > 0`。  
- `prefer`/`only` 互斥校验：同一目标不能同时选中；若存在 `only`，其他目标必须设为 `standby`。  
- 健康阈值需满足数值范围（例如 0-100%、0-5000ms）。  
- 保存失败时调用 `normalizeApiError`，并标记对应字段错误。

---

## 6. 读取/只读状态

- 租户管理员或只读角色：  
  - 列表不显示 `新建/删除` 按钮。  
  - 详情页表单禁用，显示提示“仅可查看”。  
  - `测试` Tab 仍可使用，以便验证策略。  
- 无权限用户访问详情页：跳转至 403 空态（配置在 `Permission_Guards_and_RBAC.md`）。
