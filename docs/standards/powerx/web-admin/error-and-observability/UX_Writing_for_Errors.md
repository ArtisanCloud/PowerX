# 错误文案规范（UX Writing）

> 统一 PowerX Web Admin 中的错误提示语气、结构与多语言处理，提升用户在异常场景下的理解和行动效率。

---

## 1. 基本原则

1. **先说明问题，再给行动建议**：明确发生了什么、为什么、下一步怎么做。  
2. **语气友好、专业**：避免责备用户或使用技术黑话。  
3. **保持中英文一致的语义**：多语言翻译需同步更新。  
4. **避免暴露敏感信息**：不要展示内部堆栈、服务器 IP、Token 等。

---

## 2. 文案模板

| 场景 | 建议结构 | 示例 |
| --- | --- | --- |
| 表单校验 | 问题 + 解决方案 | “API Key 格式不正确，请输入 32 位字符。” |
| 网络/服务器错误 | 状态 + 重试 | “网络连接异常，请检查网络后再试一次。” |
| 权限不足 | 说明 + 下一步 | “缺少插件安装权限，请联系管理员开通。” |
| 不可恢复错误 | 问题 + 兜底 | “加载失败，我们已记录该问题。请刷新页面或稍后再试。” |

---

## 3. 字数与语气

- 简短明了，控制在 30 字以内，避免长段落。  
- 使用礼貌语气，不要命令式：“请尝试…”，而非“必须…”。  
- 不使用拟声词或过度口语化表达。

---

## 4. 多语言指引

- 所有文案进入 i18n 资源（`i18n/locales/*.json`），Key 建议命名 `errors.<scene>.<detail>`。  
- 中文与英文版本同步提交，防止出现“缺失翻译”占位。  
- 涉及变量时使用占位符，例如：
  ```json
  {
    "errors": {
      "quotaExceeded": "操作次数达到上限（{limit} 次）。请联系管理员提升配额。"
    }
  }
  ```

---

## 5. 与 UI 组件配合

- Toast/Alert：标题 concise，描述提供更多上下文。  
- 表单：使用 `UFormGroup` 的 `help`/`error` 属性展示具体字段错误。  
- 空状态：配合插画/图标与操作按钮，避免只有文字提示。  
- 全局错误页：提供“复制错误详情”按钮，文案说明已记录。

---

## 6. 不建议的做法

- 含糊其辞：“出现错误，请稍后再试” （缺少原因）。  
- 输出原始异常字符串（例如 `Error: ECONNRESET`）。  
- 使用内部代号或英文缩写（除非在括号中解释）。  
- 一次输出过多解决方案（优先给出最有效路径）。

---

## 7. Review Checklist

- [ ] 文案是否说明问题 + 原因 + 行动。  
- [ ] 语气是否友好、无责备。  
- [ ] 多语言翻译是否齐全。  
- [ ] 是否避免泄露敏感/技术细节。  
- [ ] 是否与 UI 组件（按钮、链接）配套提供下一步操作。

---

## 8. 后续计划

- 收集常见错误场景建立文案库（如认证、配额、权限、网络）。  
- 与客服/运营团队建立反馈循环，定期优化易混淆提示。  
- 在 QA 用例中校验错误文案是否正确显示。
