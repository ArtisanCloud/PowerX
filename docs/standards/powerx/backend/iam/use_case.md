# 登录与权限模型

下面这张一眼懂 👇

| 登录身份                             | 当前上下文（tenant）  | 权限范围 / 能力                                    | 典型菜单                        | 可调用的 API 命名空间（示例）                                           | 数据可见性 / 备注                                            |
| -------------------------------- | -------------- | -------------------------------------------- | --------------------------- | ----------------------------------------------------------- | ----------------------------------------------------- |
| **Root**（系统超级账号）                 | 全局（可切入任意租户）    | 管理 **所有 Tenant**、全局 **User**，可进入任意租户做成员/组织管理 | 系统总览、租户管理、全局用户、插件市场、系统审计/安全 | `/admin/system/**`（系统级）、可代理进入 `/admin/iam/**?tenant_id=...` | 不出现在任何租户的成员列表（已过滤）；可切换/指定 tenant 查看与操作                |
| **Tenant Admin**（某租户管理员）         | 固定为 **自己的租户**  | 管理 **本租户**的组织（部门/团队/岗位）、**Member**、角色权限、业务插件 | 成员管理、部门/团队、角色与授权、业务配置       | `/admin/iam/**`（租户级）、业务侧 `/admin/<plugin>/**`               | 仅本租户数据；不可跨租户；是否能“邀请/创建成员”由租户策略决定                      |
| **Tenant Member**（普通成员/被邀请到他人租户） | 固定为 **当前所在租户** | 进行业务操作（按角色/数据域授权）；**无成员/组织管理**               | 我的工作台、业务功能菜单（CRM/电商等）       | `/app/**` 或 `/api/<plugin>/**`（业务侧）                         | 仅见到自己权限范围的数据（SELF/DEPT/ORG\_SUBTREE…）；可在“我加入的租户”间切换身份 |

### 小落地点（建议一起实现）

* **登录后决策**

    1. 如果是 `root` → 进入 **系统后台**；
    2. 否则列出该 `User` 关联的租户 Member 列表 → 选择“当前租户”进入；
    3. 进入后检查该 `Member` 是否为 **Admin**，决定显示“成员/组织管理”菜单与否。
* **路由/权限护栏**

    * 系统级：`/admin/system/**`（仅 root）
    * 租户级：`/admin/iam/**`（仅当前租户 Admin）
    * 业务侧：`/app/**`（所有成员按角色/数据域授权访问）
* **成员列表过滤 root**：租户侧 `/admin/iam/members` 永远 `username != 'root'`（或根据你的根用户标识位）。
