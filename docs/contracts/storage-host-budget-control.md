# 主机空间预算的数据库权威与同盘保护

2026-11-07，SG-11 主机预算切片。配置、回执和发布沿用[统一配置合同](storage-control-authority.md)；本轮不代表正式站已升级或全部商用门槛通过。

## 用户任务与页面

入口：“存储治理 → 自动治理 → 共享磁盘预算”，资源保留策略中的“主机空间保护”也打开同一弹层。弹层按纵向分区组织“保护概览／预算设置／进行中的预留”；窄屏使用分区选择器，切换与关闭重开保留草稿。

1. 查看配置归属、已保存／已生效／执行端快照版本和当前实际准入限制。
2. 首次明确确认“保持保护并接管预算”。旧保护值保持原样，不暂停保护、不启用写入准入、不删除文件。数据库接管产生待发布状态。
3. 首份成功发布的投影选定同盘预算的配置归属及独立 authority UUID。其他安装复用归属实例的数据库权威，只读查看共享限制；不会各自管理一份预算。
4. 在归属实例修改最低可用空间、临界余量、整盘实占与预留上限、最大并发数，确认影响范围后保存。保存成功不等于生效。
5. 版本冲突保留原表单与 CAS 基准，只能明确选择“放弃草稿并载入最新版本”。SSE 刷新不替换编辑基准。
6. 响应未知时禁止再次提交，仅 GET 原 UUID 回执。404 仍为未确认，不能授权重发。回执同时返回原操作版本与当前配置状态。

状态来自既有存储治理 SSE。初次打开、手动刷新、收到事件和重连同步可以读取；没有常驻业务状态轮询。旧后端、缺表、DB 不可用或归属不明时显示不可编辑，不回退文件写入。

## 固定范围与配置

- tenant 0、domain `host-budget`，数据库版本范围为可信 `(host_id, filesystem_id, owner_instance)`，沿用 SHA256 scope ID。
- 固定 `HostBudgetSettings`：`min_free_bytes`、`critical_free_bytes`、`max_used_bytes`、`max_concurrent`。字节均为整数，最大 2^50；最低和临界余量大于0且临界小于最低；并发1～16。
- `max_used_bytes=0` 只表示不单设整盘实占上限，其他保护继续生效。UI 以 GiB 编辑、按字节保存，零值不被替换成默认上限。
- authority UUID 取自初次接管的请求 UUID；完整旧 `BudgetPolicy` 及规范摘要作为 origin 保存。修改不改变 origin 或 authority UUID。
- 复用现有控制配置与不可变版本两表，无新表、无启动迁移、无自动接管。CAS、审计／trace、UUID回执和正式 TaskBus 登记同事务提交。

**部署前提：**同盘实例必须连接同一可信平台数据库并使用同一受保护协调目录。另建目录不构成跨实例协调；不能以一个实例的数据库配置代替这一部署要求。

同盘不同实例可同时提出初次接管候选，只有第一份在主机锁内核验旧值并成功发布的候选取得归属。失败候选保持可追踪记录，不会覆盖赢家。后续其他实例通过归属实例的 scope 读取权威，不创建第二个消费者或另一套服务端口。不同数据库没有匹配的归属版本／authority UUID时阻止准入；不自动夺取或转移归属。

## 投影与执行

原私有 `budget.json` 保留 legacy policy 与活动预留，并新增固定 `control` 执行投影：主机／文件系统／归属安装、authority UUID、确认版本／摘要、固定正文、操作者和时间。原子写入并 fsync，旧 policy不被新值覆盖。独立私有 `budget-control-binding.json` 先持久化唯一归属意图；投影缺失或绑定不匹配时，其他安装及新版独立 worker 也不能回到 legacy 准入。初次发布在写绑定后中断，可由同一正式发布幂等续做；已有投影而绑定缺失则阻止发布，不自动补造绑定。

执行逐次核对数据库期望／确认版本、不可变正文／摘要、scope、投影及接管来源。数据库单独回滚、投影丢失／篡改、错误主机、不同authority、首次发布前旧值漂移均阻止新的准入。新版无数据库钩子的独立 worker 看到受控投影也拒绝旧 JSON 保存和新增预留。

锁顺序为数据库资源锁 → 主机账本。读取投影后先核验数据库，再在同一数据库锁内复核账本身份／版本并原子登记预留。单连接池不嵌套借连接。主机锁仅在尚未进入回调时最多等待500毫秒；已进入的持久化不在本地重放。

未发布配置按保守规则合并：最低／临界余量取较高值，并发数取较小值，实占上限取较小的正值。放宽要等正式发布确认，收紧在当前数据库锁内先保护；不会以“尚未发布”扩大写入资格。UI另显示此待发布保护状态。

新增预留和扩张／续租均核验权威。DB核验最长5秒；失败后不继续扩大空间，已有任务按既有租约／取消协议收尾。释放租约不依赖数据库，避免故障期间不能释放已有预留。写入准入的启用范围仍由部署控制，不因接管或保存预算自动开启。

旧二进制不理解新投影，可能忽略字段；仍必须在 T171 的维护交接中停止旧写入者／执行器，不能新旧双跑。整套数据库＋账本同时回滚的独立恢复时代次尚未实现，仍为发布门槛。

## API 与失败合同

配置 API 前缀下的 `/admin/ops/storage/runtime/budget`，仅真实平台 Root access 用户会话可访问：

| 方法／相对路径 | 固定合同 |
| --- | --- |
| GET `/runtime/budget` | 归属、权威、保存／生效／快照版本、期望配置、实际限制、待发布保护 |
| POST `/runtime/budget/adoptions` | `request_id, legacy_revision, legacy_digest, confirm:true` |
| PUT `/runtime/budget` | `request_id, expected_revision, settings, confirm:true` |
| GET `/runtime/budget/requests/:request_id` | 原操作者的不可变请求回执，不重发写入 |

旧平铺预算正文返回400；内部旧 `SaveRuntimeBudget` 和已绑定协调者的旧 `SavePolicy` 拒绝写入。400为字段／条件错误，409为CAS／请求身份／归属／旧来源冲突，428为未接管，503为权威／表／投影不可用。503不能证明未提交。匿名、租户管理员、API Key、插件／STS服务身份不能管理主机预算；这些路由为 `root_runtime_control`，不发布服务能力或grant。

配置发布任务使用不可变数据库请求回执和 TaskBus UUID任务编号完成业务幂等；恢复副本具有独立投递编号，不复用原投递信封的不可变幂等键。恢复仍走正式 StreamDriver，历史记录和租约防止同一配置应用两次，未新增私有恢复队列。

[固定 OpenAPI](../../specs/027-monitor-center/contracts/host-budget-control.openapi.yaml)与[隔离验收记录](evidence/storage-host-budget-control-validation-20261107.json)分别记录合同和证据。

## 验收、故障处理与剩余范围

使用自有临时 PostgreSQL、私有文件、正式 TaskBus 驱动与 miniredis 验证CAS、回执、同盘竞争、单连接池、待发布限制、断库释放、投影篡改及恢复副本。实际 Gin/JWT/SSE 和真实 Nuxt 浏览器分别验收；桌面1440px、390px窄屏、明暗主题、草稿保留、未知结果只读核对和空闲无周期请求均需有记录。

故障时保留旧账本、不可变版本及未知结果，不删除 `control` 字段、手改JSON或另建协调目录绕过保护。归属转移、跨数据库迁移、全套历史恢复须进入明确维护流程；本切片没有自动接管另一台机器或转移归属的按钮。

备份／快照和数据库期限等其他配置域的接管、联合恢复时代次、旧二进制部署交接、外部KMS与SG-09真实目标及7／14天运行仍待完成。日常／生产库及策略不用于取得本轮写入或删除证据。

代码映射：`storage_budget/control.go` 管理投影、最终账本守卫与绑定；`storage_governance/budget_control.go` 管理固定DTO、数据库权威、来源与回执；`HostBudgetControl.vue` 为共享弹层；`StorageRuntimePanel.vue` 保留原入口并复用该弹层。


2026-11-08 恢复与同盘隔离：数据库恢复时预算配置重建到高于所有可信水位的新版本，保留恢复配置与现行批准投影中的更严格限制，不自动放宽。安装级 `Document` 按完整 host／filesystem／instance scope 隔离；首次升级从旧绑定确认原目录归属，其他实例使用独立文件名，共享 `budget.json`、预算归属及租约保持共用。归属丢失且不能从旧绑定重证时拒绝读取，不按启动顺序抢占。两项旧多实例预算回归已纳入统一恢复验收。
