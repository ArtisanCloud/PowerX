# 历史空消费恢复归档接入

## 目标与完成边界

将临时空消费清理器已提交的原始二进制 COPY 恢复批次复制到 Core 现有归档体系，复用 Root 策略、内容寻址对象、存储目标校验、保护与期限清退。无需新数据库表、迁移、插件升级或新常驻进程。

这是历史恢复文件的专用来源适配器，不会把每次数据库整理变成备份。普通 VACUUM 只做库内复用；物理缩容重写表和索引，均不永久保存旧业务行。正式审计期限策略沿用原有删除规则；本功能不改变其 30／90 天保留期，也不扩大临时清理的范围。

源码接入与线上交接分开验收。默认不扫描任意目录，不删除临时来源文件、操作机副本或旧恢复包；未显式注册来源时没有运行变化。尤其不能把操作机上的唯一恢复副本当作 Core 已托管的远端备份。

## 固定来源配置

使用现有 `POWERX_OPS_ARCHIVE_CONFIG` 指定的私有归档 YAML，在其顶层 `sources` 列表中追加经运维核对、Core 可读取的私有目录。以下是来源片段，不是主 `config.yaml` 的新字段：

```yaml
sources:
  - id: dev-idle-recovery
    name: dev 历史空消费恢复副本
    kind: database_files
    directory: /verified/private-recovery/powerx_dev
    audit_recovery_database: powerx_dev
    file_owner_uid: 1234
```

路径和 UID 是示例，必须现场核实后替换。目录末级名称必须与数据库标签一致；适配器只接受 `database_files` 和明确文件所有者。显式 YAML 会替代归档默认配置，因此需保留当前目录、实例、已有来源及凭据引用等必要配置，不能只用本片段覆盖整个文件。配置变更由部署流程生效；策略仍通过现有 Root 管理接口发布。不得编辑服务自动生成的 `runtime-config.yaml` 冒充正式部署配置。

Core 必须能读取私有文件；不得为了接入而把 postgres 所有的恢复文件开放给所有用户。若需要准备受限暂存副本，应先核对空间、逐文件摘要与来源回执，再移交读取权。原始文件退休需单独核对托管副本和恢复证据，本版本没有自动删除来源目录的操作。

## 输入校验与失败边界

只接受原维护器 `scripts/ops/powerx-transition-guard/idle_taskqueue` 的固定布局：

```text
powerx_dev/
  apply-<数字或 pilot>/
    run-contract.json
    batch-00000001/
      receipt.json
      traces.copy.gz
      events.copy.gz
```

- 运行合同必须明确 `automatic_backup_deletion: false` 和复查时间；合同仅作证据保存，不执行其中任何指令。
- 批次必须是 `committed`，有原恢复验证通过标记、有效时间、1–5,000 行及对应审计／通知表结构签名。
- 两份 gzip 必须同时存在，压缩字节数、压缩 SHA256、原 COPY SHA256、二进制 COPY 结构及行数均匹配。拒绝拼接 gzip、尾随数据、截断和畸形字段。
- 逐级 `openat` 固定读取对象，拒绝软链、硬链接、路径越界、错误所有者、可被组或其他用户改写的目录和非私有文件。
- `delete_intent` 等未提交批次不接入，保留为需核对输入。已提交回执或内容不匹配时整次捕获失败；不生成成功清退凭据。
- 单文件压缩及解压上限各 1 GiB；单次输入总量 4 GiB、最多 10,000 个文件。归档写入还须通过现有主机空间预算；容量不足时停止，不能提前删除恢复副本腾位置。

捕获时全量核验并再次比较写入对象的摘要。日常变更检查比较回执和文件身份，冻结输入不重复生成新任务或重置保留时间。这里复核了原恢复证据和 COPY 内容，**没有重新向线上数据库执行恢复**。

## Root 操作与保留

1. 在“存储治理 → 日志归档与追溯 → 归档策略”选择该来源和经校验的归档目标。
2. 专用提示可将本地、远端保留天数填为 30；按钮仅改草稿，不保存、不启用。Root 可按恢复要求调整，再保存并确认执行版本。该建议不是对已存策略的自动覆盖。
3. 使用现有归档执行流程捕获。新副本默认受保护，显示核验结果；原始来源保持完整。保护副本和最新恢复点不能被份数或容量压力提前删除。
4. Root 核对托管内容及恢复证据后可通过现有保护操作解除**托管副本**保护。本地份数压力不能缩短已发布保留天数；远端清退仍要求期限到达、目标已验证、远端清理已发布且对象版本匹配。最新恢复点继续保留。
5. 没有解除保护的副本不会到期自动消失。保护、待传输和无法核验的输入达到预算时需处理告警或扩容，不能靠反复创建任务绕过预算。

这不等于“所有归档永久保留”，也不等于“30 天后删除所有恢复文件”：保护副本、最新点、原始目录及操作机副本有不同的交接状态。源目录的一次性退休仍需运维交接并提供独立恢复证据；本适配器不宣称已接管该删除权。

## 验收与回滚

隔离测试应覆盖真实归档对象、固定格式和摘要、畸形输入、冻结去重、取消、30 天内的份数压力、受保护和最新副本；页面检查桌面与窄屏、来源切换和草稿保留，以及建议按钮不发送写请求。

部署后先在 dev 验证 Root 来源可见、捕获回执、远端核验和恢复取回。通过后再独立配置 prod；dev 的 24 小时事故清理例外不能复制到 prod。源码和受控浏览器测试不算实际资源交接。

回滚时先通过 Root 暂停该来源策略，保留已有对象、回执及原始恢复副本，再移除专用来源配置。不要将同一来源 ID 改成普通数据库目录以规避其保护。
