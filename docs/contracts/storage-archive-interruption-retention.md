# T158：中断采集保留与结束合同

2026-11-10。[前置执行归属与重启保护](storage-archive-process-restart.md)已实现，本轮补齐 `retain_and_close` 固定动作。范围是原任务的源码与自有资源验收，不表示日常部署、正式站接管或 T158／SG-09／SG-11 总门槛完成。

## 动作语义与前置条件

- 仅处理 `status=interrupted && interruption_pending=true` 的原采集；排除导入、恢复、迁移任务与不一致的一次性任务身份。完整快照继续使用原 Job ID 的 Retry。
- 使用真实 Root 用户会话，禁止插件、API Key、非 Root 或无用户身份。客户端只提交原任务 UUID、请求 UUID、核验版本、固定动作、审核原因和确认，不接受文件路径、任意 SQL 或网络操作。
- 已保存策略必须明确暂停归档和远端清理；一次性媒体采集没有周期策略，仍须原锁排空。正式配置控制面启用后沿用数据库权威，不回退到 JSON。新 `interruption-retain` Guard 在正式控制事务中检查当前范围、文档、已发布版本及暂停；不需要访问已失效的远端目标。
- 必须绑定既有独立恢复锚点；缺失／损坏时停止。核验版本绑定完整锚点身份与代次、实例／主机、本地任务、当前策略、来源指纹和对象集合／本地身份。最终提交在同一锚点共享锁内，恢复发布不能越过已进入的步骤。

## 只读核验与对象范围

核验是请求内的单次 SSE，离开／取消即取消请求，不创建后台任务、私有队列或自动重连。原 GC 锁和策略锁全部非阻塞，忙则拒绝。这里证明的是原策略执行锁可获得，不认证外部 pg_dump／SSH／rsync 子进程或远端接收器已退出；正式接管及重新启用前，外部执行排空仍须独立验收。最多 10000 个 CAS 对象、64 GiB、5 分钟，逐个完整 SHA256；打开根、分区和对象时不跟随软链，拒绝硬链、未知名称／类型、校验不符及读取期间变化。大对象读取中定期推送进度。

**尚未发布 Files 的采集无法可靠识别每个对象的归属。** 因此本轮保守核验并保留归档根当前全部 CAS 对象，可能包含其他任务的共享对象。staging 临时文件原位保留，不认证为已完整采集，不进入完整 Files。UI 明示这是保留证据而非释放空间或完整归档。

提交必须再次完整读取并匹配 `review_version`；不是接受浏览器的“已核验=true”。配置、来源、内容、本地身份、任务或恢复代次变化均不能沿用旧预览。页面收到元数据事件时更新原任务、保留原因草稿并要求新内容证明；事件和重连不自动核验或 POST。

## 持久化、审计与原请求

1. 先以 UUID／原输入摘要登记私有 `interruption-requests` 台账，文件及父目录同步；请求锁和全局登记锁保护并发与 10000 条上限，不轮转这些履历。
2. 再在原锁内核验、恢复锚点及当前控制 Guard 下，原子替换原 Job：`status=retained`、`phase=closed_retained`、`protected=true`、`interruption_pending=false`，保存保守对象引用、核验版本／集合摘要、原因、操作者、时间、原请求身份和终态证明。
3. 任务变更与终态证明在同一份任务文件中提交，再写最终请求回执。没有跨控制 DB 与文件系统的原子事务承诺。确认／落盘故障返回未知；GET 从已有任务和台账只读核对，不补写、解锁或重放。
4. 同 UUID 不能换任务或输入。registered 而无终态的请求再次 POST 也只返回未确认状态，不能恢复执行。4xx 明确拒绝可形成 rejected；取消／IO／控制故障保留 registered／未知，不能假定未执行。
5. 台账文件缺失时，有界扫描任务中的匹配终态证明，标明 `evidence_source=job_record`；多重匹配／损坏／输入不一致关闭。正面证明仍阻止 UUID 被其他任务或输入复用。两份证明均缺失的 404 不是此前未执行的证明。
6. SQL 回放不会抹除这两份本地文件，独立恢复代次阻止旧预览；若原任务被回放，旧回执只是历史，`current_record_matches=false`，不能重做保护或清除当前中断。此项不宣称完整文件系统恢复后仍有独立 UUID 墓碑；整站恢复仍属 SG-11 现场门槛。

结束后策略保持暂停，必须另行明确启用才允许周期采集；一次性新采集也必须另一次明确调用。不创建替代任务，不删除源文件、本地对象、临时文件或远端对象。

## 内容保护与兼容

保留引用独立于完整 Files 清单，GC 验证摘要／数量／大小／身份后将它们标为已引用。普通取消保护、下载、重传和恢复不允许用于不完整保留任务。其他没有被保留集合引用的无用对象仍可按既有受控流程回收，根目录不再因这个已经结束的任务永久保持“中断执行”围栏。

记录丢失／损坏或不一致时停止回收，不能为了释放容量缩短保护。本轮不提供保留内容的到期删除或导出认证；这需要后续独立审核动作。备份中心和存储治理均显示不完整保留状态，不把旧错误当作当前待处置状态；“审核记录”可展开查看原因、审核人、时间、原请求与保留集合。

overview 声明 `interruption_resolution_version=1`；不支持的 Core 不显示新处置入口。原 Job 状态新增 `retained`，并公开最小 `capture_retention` 审核元数据；对象引用保存在私有任务记录，接口不返回原始对象引用表。没有新数据库迁移、TaskBus 队列、租户／插件能力、普通业务准入或权限修改。

## HTTP、页面与验收

默认 Root 接口：

| 方法 | 路由 | 语义 |
| --- | --- | --- |
| GET | `/api/v1/admin/ops/backup/archives/jobs/:job_id/interruption-review` | 请求内单次 SSE，只读 progress／complete／error；完整证据才可用 |
| POST | `/api/v1/admin/ops/backup/archives/jobs/:job_id/interruption-retentions` | 固定 retain_and_close，等待本次步骤结束后返回回执，不是异步任务接纳 |
| GET | `/api/v1/admin/ops/backup/archives/interruption-requests/:request_id` | 不缓存的原 UUID 只读核对；来源、历史结论与当前记录匹配分开 |

UI 为概览／内容核验／审核确认纵向分区，窄屏使用选择器。最小原请求身份在 POST 前保存到本登录 sessionStorage，不缓存原因正文、JWT、密钥或票据。重复点击、刷新、切分区、读取失败和断线不能创建新请求或自动 POST。正面匹配且当前记录一致，或明确 rejected 回执才结束该 UI 意图；缺失、未知、错误身份及仅有恢复前历史仍保持锁定。断连提示在弹层内部可见，离开或换登录身份释放旧请求／连接。

[操作指南](../guides/deploy/027-monitor-center/usecase-us9-archive-interruption-retention.md)与[验收证据](evidence/storage-archive-disposition-validation-20261110.json)区分：

- Service race／并发、错误内容、软硬链、忙锁、版本、恢复、取消、空集合、未知／缺失／回放回执和 GC／动作保护。
- 真实 Root JWT／HTTP／SSE，自定义 API 前缀和拒绝身份。
- 自有原生 PostgreSQL／正式 TaskBus 的已发布暂停、发布版本变化及控制连接不可用；Redis 为 miniredis，未停止日常数据库。
- 生产归档组件真实 OS 进程 SIGKILL 后的新进程，对原中断采集执行保留；保留所有原 CAS SHA、编号和保护，未自动建任务。不是整套 cmd/app 重启。
- 实际 Nuxt 明暗 1440／390，草稿、确认、一次核验流、接纳后截断回复、404／503／错误回执、刷新／SSE 重连、无周期读取与一次应用提交。故障夹具先 flush 回复头再延迟断开，仅为测试；不在产品里添加固定等待。浏览器可能透明重传，不能以 retry:0 推断所有场景永不重传；同 UUID 服务端不会重复应用。
