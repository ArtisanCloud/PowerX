# 手动归档原请求核对合同

2026-11-09，T158 的一个阶段。源码及自有隔离验收不代表日常部署、OSS 验收或资源接管。

## 请求与任务身份

`request_id` 是浏览器在提交前生成的 UUID，通过 `Idempotency-Key` 发送；`job_id` 是 Core 创建的归档任务 UUID。二者用途不同。响应丢失时，浏览器保留前者，再通过只读接口找到后者，不重新生成一个请求来猜测执行结果。

- 新 UI 在 POST 前保存固定的请求 UUID、策略 UUID／版本、来源 ID 和创建时间。仅写当前登录会话的 `sessionStorage`，不含 JWT、凭据、文件内容或恢复票据。
- 存储不可用、原上下文损坏或已有未核对请求时禁止新提交。账号／登录会话和 tenant 隔离；刷新、路由返回和分区切换保留同一会话的未知请求。不同登录会话不会继承旧会话的操作资格；这不是跨账号恢复机制。
- 新 UI 的 POST body 为 `{expected_policy_revision: N}`。版本变化拒绝执行；同一请求键不得绑定另一策略版本。旧 `{}` 调用保持兼容。
- `overview.run_request_version=1` 声明服务端支持此合同。缺失或不支持时，新页面禁用手动提交并提示启动新版 Core；不以错误 POST 探测接口版本，也不改变普通业务／插件准入。

## Root 只读端点

默认路径：`GET /api/v1/admin/ops/backup/archives/policies/:policy_id/requests/:request_id`，跟随部署 API 前缀。使用真实平台 Root 用户 JWT，拒绝普通用户、API Key、STS 和 service actor；不发布租户／插件 Capability。

仅接受两个规范 UUID 路径参数，不接受 query 或请求体；`Cache-Control: no-store`。服务只扫描已有的受管任务清单，最多 10000 条，不读取当前策略或控制数据库，不创建目录、任务、重试、传输或解锁。HTTP 鉴权自身仍需可用，不能承诺整个 Core 停机时端点在线。

正面回执只包含：`request_id, policy_id, job_id, policy_revision, source_id, status, phase, remote_state, created_at, updated_at`。不含原请求摘要、目标、凭据引用、文件内容或操作者信息。匹配到的历史任务不代表当前 worker 活跃、任务完成、远端可用或允许删除。

| 结果 | 页面处理 |
| --- | --- |
| 匹配的正面 POST 回应或 GET 回执 | 校验请求、策略、版本、来源和任务身份后解除提交锁；显示原任务入口 |
| 404 未核对到 | 保留原编号和锁；不证明此前未执行 |
| 409 归属冲突或正面回执身份不匹配 | 保留原编号和锁，显示错误 |
| 503、损坏／缺失清单、重复匹配、断连或不完整 JSON | 继续未知，不信任浏览器缓存作为服务端回执 |
| 新接口未加载 | 禁止新提交，提示由用户启动新版 Core |

没有任务回执的拒绝同样保持待核对；本轮不提供“清缓存／放弃未知请求”来重开新任务。需要运维排查原编号、运行代次、原清单及恢复历史；不得补造回执或把 404 改写成未执行。

## 应用与传输边界

应用层不在响应丢失、SSE／重连、刷新、读取失败、404 或按钮重复点击时自动 POST。只读核对由用户显式触发；状态仍通过共享 SSE 失效通知同步，无周期状态查询。

HTTP 响应头返回前发生 socket 故障时，浏览器传输层可能透明重传同一次 fetch。本轮分开记录应用 fetch 次数和 HTTP 请求次数；重传必须保持原 `Idempotency-Key`，由服务端幂等保护返回同一任务。不能用应用 `retry:0` 承诺网络上永远只有一个 HTTP 包或请求。收到可验证的原任务回应后，页面可正常记录它；不必继续把已有正面证据显示为未知。
