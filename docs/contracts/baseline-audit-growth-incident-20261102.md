# 权限读取导致的审计增长：修复与上线验收

## 已验证现场

2026-11-02 20:25（Asia/Shanghai）只读统计：正式库 `powerx_pro` 约 32.38 GiB，开发库约 238 MiB。正式库调用追踪约 24.82 GiB、调用结果通知约 7.48 GiB，两者合计约 99.77%，大小包含索引。插件业务 schema 约 22 MiB。

最新一万条追踪均为 `com.corex.iam.authorization_baseline.service_read`，约十一分钟产生一万次；近期调用者样本为 AI Craft。生产插件二进制的通知 worker 为 2 秒 ticker，`deliverHostNotice` 在去重 claim 前读取权限。现场有 136 条 WS 失败回执，最高重试 10477 次。失败传输返回 `HOST_PUBLISH_FAILED`；该代码本身不足以确定底层错误，也不能证明历史所有记录均由同一触发点产生。

生产插件为 `0.1.77`，构建 revision `310ed0f4efc6f5fe32d8192e2e7a45c8bc13adf2` 且 `vcs.modified=true`；本地没有对应完整源码对象。已直接核对线上二进制的定时常量与调用顺序，不能用本地新卡片实现冒充线上旧版本的调用路径。

## 修复归属

| 层 | 本次处理 |
| --- | --- |
| 插件通知 | 失败上限、指数退避、隔离保留、同一内容版本成功通道去重、显式有回执恢复 |
| 插件权限读取 | 本轮批量合并无变化卡片检查；实际发送仍重新判权，不增加跨请求授权缓存 |
| Core 调用审计 | 保留必要调用追踪；新增回归证明重复调用不会被静默采样丢弃，无确认发布不能假称完成 |
| Core 生命周期 | 复验现有发布状态回写、显式保留策略、待确认/未知/外来引用保护及默认关闭边界 |

本次不关闭 PostgreSQL 修改日志、不关闭 RBAC、不删除业务事件。插件细节与操作合同位于插件仓库 `docs/contracts/order-content-delivery-retry.md`。

## 上线前与顺序

1. 确认 Core、Framework 和插件来自可追溯的同一交付版本。生产旧通知模型缺少本地新模型字段，不可只覆盖一个新插件二进制。
2. 做可恢复的数据库备份，按正常集中迁移路径完成版本要求的 schema 升级；修复命令不得挂入启动或迁移。
3. 核对 WS 发布的目标、认证、正式 TaskBus 契约与 topic/tenant/trace；修复 `HOST_PUBLISH_FAILED` 的真实原因，再安排切换进程与真实通知验收。
4. 接入存储治理运行时，确认实例/租户登记、工作线程、两张审计表分类与索引已就绪。监控启用不等于清理策略已启用。
5. 在 UI 中明确保存审计期限、容量预算和历史分类接管选项。候选值可评审成功 7 天、失败 30 天、待确认 24 小时后核对/隔离；这些数值是待确认建议，本次未启用。
6. 先预览历史审计记录。旧 `pending` 不能按成功数据直接删除；必须核对关联追踪、topic、载荷证据和隔离宽限期。不要把调用结果通知与插件业务 outbox 混为一类。

这些步骤不构成已授权的生产部署、重启、迁移或数据库清理；本次生产数据与运行进程保持不变。

## 验收

- 同一事件 WS 失败时，已成功的 Host 通知不重复创建、不额外逐次读取权限。
- 退避窗口内不再发起该事件的投递；达到上限后保留隔离状态并停止自动尝试，显式恢复带原始计数及持久化回执。
- 无变化卡片检查对同批成员只作批量权限读取；撤权、授权版本、有效期、成本范围、发送前校验继续生效。
- 新调用结果不长期遗留错误的 `pending`；没有发布确认时保存 `unconfirmed`，不声明业务消费完成。
- 跟踪上线前后至少两个调度窗口和一小时的真实新增量，观察通知成功率、重复请求比例、审计新增行数、数据库大小与文件系统空间。

本地隔离 PostgreSQL 测试使用本机可用的 PostgreSQL 14，验证行锁与并发恢复；这不替代生产 PostgreSQL 16 的升级和安装态验收。

## 本轮验证结果

- 插件通知、权限、投递仓储与恢复命令四个相关包的受控测试和 race 检查通过；隔离 PostgreSQL 的并发恢复、预览只读与缺失 schema 不创建检查通过。
- Core 调用审计、审计保留仓储和存储治理三个相关包的受控测试及 race 检查通过；默认关闭、未知发布保留、历史分类接管等边界保持原合同。
- Core/插件相关 `go vet`、本机构建、Linux amd64 构建、恢复命令 Linux 构建通过；插件 Host TaskBus 凭据选择测试和两个恢复 Make 入口的只读解析检查通过。
- Agent 创建的临时 PostgreSQL 已停止，PID 退出、Unix socket 和数据目录清理均已确认。没有重启用户服务。
- 未运行整仓全量测试、真实模型、生产迁移、历史数据删除或真实通知投递验收。原始 WS 传输失败原因尚未由现有错误代码确定。

工作区 `tmp/baseline-audit-remediation-20261102/validation.json` 保存源码哈希、任务独立补丁、验证日志与候选二进制哈希。补丁只包含本任务相对原有工作区的变化，原有脏改动保留；候选构建未经上传或安装，不是干净签名的正式发布包。正式升级应使用新的不可变版本号，不覆盖现有 `0.1.77` 安装目录。

## 空间回收边界

清理旧行与释放文件系统空间是不同操作。普通删除配合 VACUUM 主要让数据库复用已有页，并不保证两张大表立即缩小。当前业务空间已腾出缓冲，优先限制新增长并安全复用旧页；需要缩小文件时，单独安排扩容后重组、迁移到独立实例等维护方案。

不得在剩余空间不足、没有恢复验证或没有维护窗口时运行 `VACUUM FULL`、重建大表/索引或删除整个 PostgreSQL 数据目录。图片/备份迁至私有 OSS、数据库迁至独立实例应继续推进，同时保留配额、期限与告警。
