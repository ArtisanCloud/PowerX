# 归档目标凭据的独立加密存储

2026-11-06，SG-11／T170 的文件密钥提供器切片。进度仍以 [T166～T174](../../specs/027-monitor-center/tasks.md#us9-commercial-gates) 为准；归档目标及策略随后按专用合同接入数据库；外部 KMS、完整恢复时代次及长期运行验收尚未完成。

## 产品流程

入口为“存储治理 → 日志归档与追溯 → 存储目标 → 管理归档凭据”，也可从资源配置内进入同一个管理弹层。默认“凭据清单”，另一分区为“填写凭据”；桌面纵向导航、窄屏选择器，切换保留未提交内容。错误、存储不可用、主密钥轮换及未知请求状态始终可见。

1. 查看旧配置来源及版本；未准备独立存储时仅可观察，不能继续创建明文凭据。
2. 明确确认“接管并加密”。服务器核对旧版本与摘要，将值复制到独立加密权威，保留原配置对象作为证据。浏览器不读取旧 AccessKey／SecretKey。
3. 新建或更新凭据需要显式引用和期望版本，提交带 UUID。敏感输入只在当前表单内存暂存，提交结束和离开组件时清除；不写 localStorage、URL 或普通配置草稿。
4. 接管、替换、吊销、活动主密钥变化或重新加密都会使旧目标验证证明失效。须重新进行目标写入／完整取回校验，再按原归档合同明确启用策略。保存凭据不会开启归档或传输。
5. 吊销将当前活动值从加密账本移除并递增版本，保留审计回执。读取不能转回原部署配置或旧 secrets 文件。恢复使用需明确填写一个新版本。
6. 响应丢失或格式不明后，只查询原 UUID 回执；404 不能证明在途操作未发生。版本冲突保留引用和基准版本，敏感值已经清除，核对最新状态后重新填写；不自动覆盖或重发。

UI 复用既有备份 SSE。凭据账本及外部密钥目录变化仅推送资源失效通知，不传文件内容；初次载入、手动刷新、变更事件及重连后读取元数据，不周期查询状态。

## 部署合同

独立文件密钥提供器配置位于既有 `POWERX_OPS_ARCHIVE_CONFIG` 的归档配置中。服务不创建目录或主密钥，不执行 chmod／chown，不从聊天、URL或浏览器接收主密钥。部署方预先准备目录和密钥挂载：

```yaml
# 原有 directory、instance、execution_node_id、sources 保持部署方真实配置。
credential_vault:
  store_id: archive-credentials-prod
  directory: /var/lib/powerx-credentials/prod
  keyring_file: /run/powerx-keys/archive-keyring.json
```

密文目录必须在归档运维目录之外，主密钥文件同时在归档目录和密文目录之外。路径在部署绑定时解析并固定；父级软链、最终目录身份变化、文件软链／硬链、非服务进程属主或过宽权限均拒绝。密文目录 0700，密钥及账本文件不得开放组或其他用户权限（0600／0400 等只对服务 UID 可读的模式）。容器挂载需配置实际运行 UID；服务不会放宽权限来适配不正确挂载。

外部文件密钥合同为 JSON，**以下是结构说明，密钥占位符不能直接使用**：

```json
{
  "version": 1,
  "store_id": "archive-credentials-prod",
  "active_key_id": "master-2026-11",
  "keys": {
    "master-2026-11": "<由部署密钥管理系统生成并挂载的32字节随机密钥的Base64>"
  }
}
```

允许最多16个读密钥，以支持分阶段轮换；active_key_id 必须存在。密钥文件与密文必须独立备份、控制访问与保留。此实现是明确的文件密钥提供器，不是外部 KMS／Vault 服务的接入声明。

## 权威、事务与保密

主密钥仅在外部挂载文件中，凭据唯一写入权威为独立目录的 `credentials.sealed.json`，不依赖业务数据库。数据库中的后续归档目标配置仅应保存引用和版本；归档目标已由后续[目标控制合同](archive-target-control.md)接入数据库；策略也已按[策略控制合同](archive-policy-control.md)接入，完整商用门槛仍待关闭。

加密使用固定 AES-256-GCM、独立随机 nonce；协议版本、store_id、安装 scope 和 key_id 参与认证。账本内的引用、版本、吊销状态、来源证据、操作人、Trace 和 UUID 回执一起被认证加密。请求摘要为账本内随机专用键的 HMAC，不把请求中的密钥值当普通摘要或审计正文公开。

所有读取重新检查目录身份、文件属主／权限／链接、外部密钥及认证标签，不缓存解密凭据。密钥缺失、错误、损坏或当前 key_id 不再允许时，状态不可用，不能自动生成替代主密钥或回退明文。密文和密钥来自不同安装 scope 时也拒绝。

同一个文件锁内核对版本和请求身份，并将凭据状态与回执一次写入新密文：私有临时文件 → fsync → 原子替换 → 目录 fsync。只在尚未进入回调时有界等待锁，已经执行的持久化不重试。相同操作者、UUID 和载荷返回原操作；同键异载荷冲突。回执仅原 Root 提交者可查询，与当前存储状态分别返回。

账本上限4MiB、256个引用及2048个回执；达到上限拒绝写入，不自动清除审计或历史请求。后续需专项保留／迁移流程，不能将它交给普通日志清理器。

第一次有效写入前，在普通归档元数据写入不含密钥的提供器绑定，绑定 store_id、安装身份及规范化位置摘要。之后移除或改变提供器配置会阻止明文回退。绑定内另存各引用已批准的最低凭据版本，并在密文提交前 fsync。这能阻止仅回滚／删除密文账本后复活旧凭据；保护性下限已写入而密文未提交的未知窗口会锁住使用，必须核对回执和恢复流程，不能当成空库重建。启动不会创建绑定、导入旧值或启用策略。

启用独立提供器后，发布的归档 runtime-config 不再复制旧 S3Credentials 值，只发布提供器引用。旧部署配置、旧 secrets 文件和此前产生的历史快照仍可能含旧值，本轮按要求保留；必须完成受控接管、独立恢复核对及引用盘点后另行处置，不能将历史对象也宣称为已加密。业务媒体来源的 S3 凭据不是本合同的归档目标凭据，不在此切片替换范围。

## 主密钥轮换与吊销

1. 部署方在外部 keyring 新增随机32字节密钥，将 active_key_id 改到新 ID，同时保留旧 ID。建议原子替换挂载文件。
2. SSE 使页面显示“主密钥轮换尚未完成”，禁止普通凭据修改与新的凭据使用。活动密钥身份已纳入目标指纹，旧目标验证立即失效。
3. Root 在 UI 明确选择“重新加密到当前主密钥”。以当前账本版本 CAS 重新加密全部凭据与回执，不改变云端 AccessKey，也不启用传输。
4. 核对账本 key_id、读取及独立恢复后，再从外部 keyring 移除旧密钥。若提前移除解密所需旧键，服务阻止操作，不自行恢复或重新生成。
5. 云端 AccessKey 的实际吊销还需在云服务商完成。本地吊销阻止 PowerX 后续通过该引用使用凭据，但不能撤销已经在途的网络请求或其他持有旧 Key 的系统。

目标指纹包含独立提供器、密文 key_id、活动 key_id、引用与凭据版本。每个既有传输批次仍使用原目标／策略核对；轮换、吊销后不再把旧验证当成有效证明。本切片不声称能取消已进入远端服务的请求。

## 接口与故障处理

[OpenAPI](../../specs/027-monitor-center/contracts/archive-credentials.openapi.yaml) 使用可配置前缀。以下均以 `/admin/ops/backup/archives` 为根，要求真实平台 Root 用户 access JWT，拒绝 API Key、STS 和服务身份：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/s3-credentials` | 引用、状态、版本与提供器准备情况，不返回值 |
| POST | `/s3-credentials` | UUID＋期望版本＋新凭据，固定 DTO，上限32KiB |
| POST | `/s3-credentials/{ref}/adoptions` | 旧版本、摘要及明确确认，复制旧值到加密权威 |
| POST | `/s3-credentials/{ref}/revocations` | 期望凭据版本及明确确认，吊销当前引用 |
| POST | `/credential-store/rotations` | 期望账本版本及明确确认，只重新加密到部署方活动密钥 |
| GET | `/s3-credentials/requests/{uuid}` | 原提交者只读核对原请求，未知不重放 |

| 状况 | 处理 |
| --- | --- |
| 未配置提供器 | 旧来源只读；新写入503，不产生新的明文文件 |
| 版本冲突／键复用 | 409，核对当前状态与原请求，不能自动换版本覆盖 |
| 响应丢失 | 按原 UUID 查回执；404仍保持待核对 |
| 密钥缺失、权限、链接或认证错误 | 状态不可用，修复挂载／身份，不生成替代密钥 |
| 主密钥轮换待完成 | 先按轮换顺序重新加密，再修改凭据；勿先删除旧键 |
| 提供器位置变化 | 绑定拒绝，走受控迁移／恢复，不删除绑定来绕过 |
| 回退程序 | 先冻结传输并核对在途状态；禁止旧版本恢复明文写入或忽略提供器绑定 |

## 恢复与交付边界

独立恢复需要同时取得密文账本、正确的外部读密钥、store_id、安装 scope 和归档目标元数据。应恢复到新的隔离目录先核对，不得直接把历史账本覆盖在线现用目录。测试证明“相同 scope 的密文及密钥可以在独立目录解密”和“缺密钥／错误 scope 不可读”，不是生产恢复授权。

当前尚无覆盖整个账本、绑定和数据库同时回滚的独立恢复时代次保护。历史完整备份回滚可能回滚吊销及版本状态，必须作为 T171 发布阻塞项，不能用本轮加密验收关闭。独立密钥的异地保管、外部 KMS、旧对象最终删除、凭据与所有资源的完整导出／恢复、SG-09远端取回及7／14天运行要求仍待后续验收；目标／策略数据库接管已由后续专用合同实现并隔离验证。

## 2026-11-08 恢复代次

托管恢复的独立维护代次绑定到加密记录及不可变回执。历史 active 记录与旧明文来源显示 `recovery_required`，执行路径拒绝读取；Root 必须重新保存明确提供的值，再对目标执行完整验证。`adopt` 和主密钥重新加密不能把历史值转为本代次证明；历史 UUID 回执仍可读取，但不激活凭据。新一轮恢复立即使上一轮凭据和目标验证失效；缺失维护证明失效关闭。目标指纹同时绑定当前代次与凭据身份。

独立密文账本／外部密钥及运行版本下限不一致时仍拒绝操作，须恢复匹配的密钥和权威账本，不能抹掉绑定绕过。此处不是外部 KMS 恢复或远端账号吊销的证明。SSH 暂无同等代次确认合同，恢复后保留阻止状态。详见[统一恢复合同](storage-execution-control.md#2026-11-08-统一重建与逐资源核对)。
