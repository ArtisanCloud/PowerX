# 旧执行器只读盘点与交接预演

2026-11-09，T171 的现场交接准备切片。工具为 `scripts/ops/powerx-space-guard/handoff_inventory.py`，使用方式见[交接手册场景 D](../guides/deploy/027-monitor-center/usecase-us9-storage-execution.md#场景-d旧执行器只读盘点与预演2026-11-09)。

## 输入、输出与权限

直接在目标 Linux 主机运行，读取已知部署程序、systemd、cron、可见进程、来源绑定及 Core 的有时效控制文件。建议由主机运维身份执行，以便完整读取；权限不足必须返回 unknown，不能按没有任务处理。没有数据库连接、Root JWT、SSH 凭据或对象存储凭据参数。

工具不执行迁移、停止／禁用服务、建立绑定、清理文件或启用策略，没有 `--apply`。默认只向 stdout 输出报告；`--output` 只独占创建新的 0600 证据文件，已存在时失败，不覆盖。`--root` 指定导出树时始终为 `snapshot`，禁止查询真实主机的 systemd／进程；快照中的链接不得逃逸到真实主机。

报告 `schema=powerx.executor-handoff/v1`，包含：

| 字段 | 语义 |
| --- | --- |
| `mode` | `live_linux` 为本机实时只读采样；`snapshot` 不证明现场状态 |
| `summary` | 已核实程序、活动／已启用调度、失败服务、cron 命中、可见进程、登记来源及待核对项数量 |
| `binding_state` / `control_state` | 固定程序／来源绑定与 Core 当前有效发布分别核对；控制文件过期不代表旧执行器重新获得来源 |
| `programs` | 仅路径、角色、文件属主／权限、SHA-256 和协议检查，不导出源码 |
| `units` | `active/scheduled/inactive/failed/not_found/unknown`，保留 Result 与退出码；失败不能显示为空闲，inactive 的 enabled timer 仍是 scheduled |
| `cron` | 文件元数据、命中行号及固定任务类别，不含原始命令／环境变量 |
| `processes` | PID、PPID、UID、内核启动 tick 和固定类别，不包含参数、环境或凭据；pg_dump／pg_restore 的实际归属须另核对 |
| `guard_run` | 默认守护 latest.json 的状态、时间、错误数量及容量数字；不导出原始错误或其他正文。15 分钟外标为 stale，不能作为当前容量判断 |
| `sources` | 已核对绑定的目录身份与隔离区计数，不读取业务文件或隔离内容 |
| `basis_sha256` / `comparison` | 本次盘点依据及与上份报告的变化；心跳、程序、调度或来源变化均可能要求重新检查 |
| `authorizes_switch` | 始终为 false；报告与比较结果都不是执行票据，Core 不接受其作为自动完成交接的证明 |

`registered_sources=0` 或 `pending_quarantine_sources=0` 在绑定／控制未知时不代表不存在来源或未确认数据。必须同时查看 `binding_state`、`control_state`、`problems`。返回码 0 只表示形成报告；不能用退出码授权停止旧任务。

## 覆盖与失效边界

- 读取已知四个 PowerX 维护程序；绑定核对 guard／helper／policy 的实际哈希和协议。不得通过只加协议常量或改写绑定哈希伪装升级。
- 检查标准服务、使用相关脚本的自定义系统服务、timer 与 `.service.d/*.conf` 覆盖；每个 unit 目录最多 2048 项、每个覆盖目录 64 项、最多查询 64 个 unit。systemd 仅执行固定 `show` 命令，超时或权限错误保留 unknown。
- 指向受信 `/dev/null` 字符设备的系统 mask 单独列为 `masked_unit_files`，不读取字符设备内容，也不把无关 mask 误报为脚本；已知 PowerX unit 仍查询实时状态。此例外不放宽绑定／控制文件的链接检查。
- 有界扫描系统和用户 crontab 文件。at 队列、容器、user systemd manager、其他主机、未知封装脚本及 Core 已接纳／排队长任务不由此报告证明。进程扫描也不是全机原子快照。
- 控制／绑定文件拒绝软硬链接、异常权限／属主、过大文件、身份／来源重复及发布过期。程序或正文读取期间变化使本次核对失败。系统 unit 的正常受信链接可读取；离线快照链接仍须位于导出根内。
- 时间按带时区的 RFC3339 核对，支持 Go 的 Z／纳秒并规范化以兼容 Python 3.9／3.10；无时区或损坏时间不当作有效发布。默认守护状态路径不同、不可读或损坏时显示 unknown，不猜测为成功。
- `.powerx-audit-custody` 非空或不可读取必须先核对历史回收结果，不移动、清空或重做未知操作。
- 旧 guard 还可能承担 logrotate、journal、系统日志和容量观察；只接管部分来源不能直接停整套 timer。支持新版固定绑定的 guard 可继续维护未转移职责，不能继续处理已接管来源。

## 实际交接顺序

1. 完成长期在线目标、真实取回及正式构建验证；本机隔离 MinIO 不替代现场证据。
2. 在目标 Core 的 `/monitor/storage` 进入“执行器交接”，开始交接并锁定；逐资源暂停自动策略并等待正式发布。未配置全局保护时须明确接入，不因读取报告而自动接入。
3. 运维检查本报告、发布版本、来源清单、隔离数据、旧程序／调度和已接纳任务，明确每项来源的唯一执行器与回退办法。报告不代替两项人员声明。
4. 在另行批准的维护步骤中部署经过验证且识别新协议的程序、核对绑定预览，再改变选定来源的绑定／旧入口。若仍有未迁移职责，不停共享 guard。重新生成报告比较变化；没有自动 apply 或报告导入接口。
5. 完成交接仍保持暂停；单独恢复全局开关，再逐项启用资源策略，开始真实运行验收。失败保留暂停、版本及历史结果，不能删除绑定／水位回退旧执行器。
