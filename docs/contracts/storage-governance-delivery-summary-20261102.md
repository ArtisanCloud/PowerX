# 存储治理机制阶段交付总结（2026-11-02）

本轮完成 PowerX 存储观测、显式清理策略、可取回归档和容量保护的本地开发交付及实际日常实例验收，可以作为一个阶段提交。该结论不代表生产已部署、长期策略已经开启或全部 US9 规划项完成。

## 已交付范围

| 范围 | 最终行为 |
|---|---|
| 占用与历史 | 分开显示整盘、当前环境数据库、登记目录和共享来源；约五分钟持久化有界摘要，未知和未接入不算作零占用 |
| 文件清理 | Root 显式选择关闭、安全到期删除、验证归档后删除；保留活动文件、最新封存、稳定窗口和不可信文件；限批次、幂等、意图先落盘，中断结果保留未知 |
| 原生 PostgreSQL 日志 | 动态读取受信任 `current_logfiles`；共享集群单列，原子捕获后复查打开句柄；清单变化、工具缺失或无法核验时保留原件 |
| 独立归档 | UI 配置私有目标及凭据引用，保存／测试／开启分开；具体对象与清单版本完整读回校验，关闭归档不自动开启删除 |
| 历史与取回 | 持久目录、检索、预览、下载、旧清单纳管／迁移、远端版本到期与引用保护；原来源或本地缓存消失后仍可取回已验证归档 |
| 数据库期限 | 调用审计及通知事件分类、终态／发布回执、pending 核验隔离、引用保护、有界事务批次；旧未知记录默认保留 |
| 容量保护 | 共享同盘预算、在途预留和写入准入；可独立保护能力调用，在业务副作用前拒绝；物理占用与删行分开核算 |
| 运行与交付 | Core 启动时接入观测和调度；SSE／WS 事件同步；普通 Loki 出口有界异步；旧守护器有明确接管协议 |
| 管理页面 | 按任务分区，存储与备份复用归档组件；桌面／窄屏、表单保留、错误与禁用边界有测试和验收记录 |

## 已有验证证据

- [连续十五分钟文件治理](evidence/storage-stable-window-validation-20261101.json)：日常实例正常 Root 配置后，后台自动清理自有过期样例，既有日志受保护，最终恢复暂停。
- [数据库期限与容量保护](evidence/storage-database-admission-validation-20261102.json)：隔离真实 PostgreSQL 的 HTTP／gRPC、终态／pending 保护、有界批次与普通 VACUUM 验证；不等同于日常数据库清理已开启。
- [实际 Root 归档／清理／取回](evidence/storage-installed-root-validation-20261102.json)：真实页面和正式接口使用自有私有版本 MinIO；仅回收自建 59 字节原件，源与本地缓存消失后取回哈希一致；临时对象及服务已收尾。
- [原生 PG、监控与通知](evidence/storage-native-observation-validation-20261102.json)：操作者重启后日常 Core 读取新配置；正常两轮五分钟采样包含共享 PG 来源，Root 站内告警交付且通知中心可读，重复观测没有重复发送同一告警。
- [可重复原生 UI 组合验收](evidence/storage-archive-native-ui-validation-20261102.json)：真实 Nuxt 产物、正式 API／SSE 与独立 S3，包含 1440／390／320 页面检查；受控身份的证明范围在记录中单列。

提交前另对拟提交 Go 源码使用 compiler overlay 核对，排除工作区其他未提交 Go 功能并使用基线依赖文件；这不是新分支或 worktree。运行期直接读取的外部文件和已记录的日常实例证据仍分别说明，不把 overlay 编译扩大为整个工作区或生产镜像的验收。

扩大 race 检查发现并修复归档远端清理启动时的状态对象并发读写；接口返回冻结的 `queued` 快照，后台独立推进并持久化。旧日志异步清理测试改为有上限地等待实际结果，避免固定 10ms 在负载下误报。

## 当前运行状态与启用边界

- 本地监控、共享预算和 Root 站内告警已接通；PG SQL 日志保持开启。
- 本地文件清理保持暂停，PG 来源没有保存开启的策略，归档策略／目标／任务为零，数据库期限策略未启用。
- 原有应用日志中的 3650 天／10 GiB 是已暂停的验收配置，不是推荐的正式留存承诺。
- 配置及私有凭据、数据库备份、原有 Mac 对象和临时运行目录不进入提交。
- 当前提交按存储治理范围拆分公共文件；AI、插件市场、业务通知卡片和其他 TaskBus／Redis 改动另行保留。

## 后续独立任务

1. 在 UI 明确实际保留期限、预算和清理模式；需要归档时选择长期在线的私有目标，验证后再开启。
2. 评估生产容量与备份，审核迁移计划；部署后逐来源移交旧脚本，不让两个执行器同时管理同一来源。
3. 真实 Mac 旧对象先纳管／迁移并验证取回，再按已确认范围处置；本轮没有删除既有对象。
4. 长期开页的右上角通知浮层在后端重启后曾未及时同步；通知中心刷新后可读。该现象尚未独立复现和修复，不用通知落库代替全部实时重连验收。
5. 七／十四天运行、双环境、完整插件库／真实流入量／压缩率／R95 和所有外部写入入口的完整覆盖仍按正式 tasks 推进。

`make unit-test` 当前因仓库缺少 `backend/test-silent.sh` 无法执行，不能报告全仓单测通过。受影响包和前端存储测试的独立结果见提交核对记录。
