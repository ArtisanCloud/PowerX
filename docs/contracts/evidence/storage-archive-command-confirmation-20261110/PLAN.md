# T158 命令启动身份与人工排空确认

- 新命令记录内核启动身份（PID、PGID、UID、进程开始标记、主机启动和命名空间摘要）；不保存参数／环境／DSN，不按裸 PID 发信号。旧 idle/drained 兼容；旧 running/prepared 缺身份仍保护。
- Root GET 原任务命令核对：固定任务／执行／命令、当前暂停策略、恢复代次、主机／启动身份、当前 leader 和组观察。只允许同主机同启动身份、原 leader 缺失且原组缺失、记录完整的 running 命令进入确认；单独缺 PID、身份不符、旧记录、活动锁、恢复变化均不放行。
- 人工明确填写原因并确认。唯一效果是按 command_id 原子写不可变 command-confirmations/<command_id>.json，内含新 request UUID／输入摘要／版本／原命令全文摘要／任务身份／恢复代次／人员／原因／时间／观察事实。它同时是终态回执和匹配该命令的本机排空证明；不改原任务、原命令、CAS、源、远端、策略或开关。
- 当前命令状态通过精确匹配该不可变回执派生 drained；新命令或新执行、回放／恢复、主机或启动变化、缺失／损坏均不继承。完成后原采集仍中断，需独立核验内容和处置。
- 原请求 GET 有界查不可变回执；确认回复丢失只读原 UUID，不重放，不换号；同 UUID 输入改变或同命令再确认拒绝。无第二个索引或跨存储原子提交承诺。
- UI 概览／只读核对／审核确认纵向分区，窄屏选择；草稿、原意图、SSE 断线和结果保持。旧 Core 不支持时不可提交。不新增轮询／私有队列／DB migration。
- 验收：真实孤儿命令活跃／外部结束后核对、PID 重用／缺证／代次／并发／回放、原生控制库断连、Root HTTP、自有后端实际 UI 的丢失回复、坏回执和恢复。只用自有资源，交付前清理。
- 不替代旧执行器现场交接、Linux 原生运行、远端接收器、OSS、完整主机回退墓碑和长期运行证据。

## 实现与结果

- 原任务命令的内核身份、暂停／锁／恢复核对、不可变正向证明、派生匹配及 Root HTTP／UI 已接入。原运行记录不修改，无任意信号入口。
- 增加确定的写入前 rejected 回执，避免断控制连接等明确未接纳请求永久卡住；进入正向写入后的错误仍未知。每个请求锁绑定不可变输入，正向／拒绝文件只会写其一，不做跨文件原子提交承诺。
- 目标探测没有 job，明确保持不支持确认，不拼造任务；下一项绑定真实目标及所有引用暂停策略后再支持。旧协议无身份不自动升级。
- 三个后端包完整 race／vet、原生 PostgreSQL／TaskBus、真实孤儿与外部结束、Root HTTP、78 前端用例及实际 Nuxt 明暗1440/390的丢回复／坏回执／刷新／SSE通过；Linux仅交叉编译。UI与受控 final-ack 丢失夹具不冒称整套 Core 崩溃。
- 无日常 Core／Nuxt重启、日常库迁移、生产接管或用户对象操作；自有资源在交付前清理。
