# T158 外部采集命令退出与排空

- 统一 pg_dump、ssh、rsync 本机命令：独立进程组；在回收 leader 前观察退出，取消先 TERM 再有界 KILL，正常 leader 退出也清理残留同组子进程，随后 Wait 和确认组消失。只向本次直接创建且未回收 leader 的组发送信号，避免重用 PID。
- 私有 command-executions 台账在 fork 前 prepared，启动后 running，确认本机组消失才 drained；记录本机 PID/PGID、操作种类、原任务/执行 nonce，不记录参数、DSN、环境或密钥。
- 每个新执行初始化 idle 证明，任务保存协议标记；丢失/损坏/未终态不能推断未执行。SIGKILL 后不按裸 PID 自动补杀或补认证；旧任务无协议同样不自动认证。原任务处置、回收及替代执行保持保护。
- 活跃命令与失主未确认分开观测；新增 UI 可读状态复用已有 SSE，不新增队列/轮询。SSH 本机组排空不证明异地接收器退出，远端结果仍按原任务核对。
- 用自有 PG 阻塞真实 pg_dump；自有 SSH 接收器运行真实 ssh/rsync；实际父进程 SIGKILL、TERM 忽略子进程、丢失/损坏证明及原任务围栏回归。仅使用自有资源，交付前关闭并检查端口/PID。
- 无需日常服务重启、迁移或 OSS；不操作生产、业务数据或既有归档对象。遗留/未知进程的人工证明解锁另作为下一独立项，不暴露清标记按钮。

## 实现与验收

- 本机三类命令已接入；每次 fork 前持久化准备状态，直接 leader 回收前完成组信号，Close 等待直接 API 与 worker。
- 失主／丢失／旧版本保护不自动迁移；Root 历史结案回执同样要求当前本机证明。未改变业务调用、权限或 DB schema readiness。
- 自有 PostgreSQL14 Unix socket 55451；真实 pg_dump 表锁等待后退出，源／CAS 保留；真实 SSH／rsync 子进程、忽略 TERM 树、父组件 SIGKILL 分别验证。
- 前端67项、真实 Nuxt 明暗1440/390、SSE／空闲请求／原任务可发现通过。UI prepared 状态与测试专用 drain 只属于自有无 fork 夹具，不是产品解锁接口。
- 首次整包的 captureTest 曾在释放采集锁与重新取得清理锁之间提前返回，导致恢复测试拿到忙锁；改为等待原 execution 完成后重跑，不修改生产锁语义。UI 脚本修正了 footer 和嵌套 select 的定位，不修改产品来迎合测试。
- 下一项补齐启动身份及人工排空证明的受控确认；不是清标记或按裸 PID 杀进程。无日常重启、远程接管或用户对象删除。
