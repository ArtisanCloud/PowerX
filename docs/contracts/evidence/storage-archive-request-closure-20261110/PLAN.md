# T158 registered 无终态请求：人工核对与受控结案

- 只处理原台账为 registered 且当前原任务仍 interrupted / interruption_pending 的请求。原请求锁、GC 锁、原策略锁必须可取得；当前策略暂停并通过正式发布控制，恢复锚可读。
- 只读核对绑定原 UUID、原输入摘要、原登记代次、当前恢复代次、当前任务全文、当前策略和主机身份。代次变化明确显示，不推断此前没有执行；不扫描或认证 CAS 内容。
- Root 明确填写原因并确认 close_unknown_keep_protection。新结案 UUID、原输入、预览摘要、当前任务摘要、代次摘要、人员、原因和时间同原台账一次原子持久化。唯一效果是记录“历史结果未知，已人工结案”；不改任务或对象、不解除 interruption_pending、不启动任务。
- 原 UUID 永久只读；结案重放只读返回原回执，改输入/并发/旧预览拒绝。确认回复丢失后按原请求 GET，浏览器保存最小结案意图且不自动 POST。404、历史不匹配、损坏、恢复变化不释放意图。
- 现存保护核对为任务全文和恢复代次匹配，读取失败保持未知。后续须独立重新核验内容，再用新请求处置原任务。不得把结案当成采集完整或可删除证明。
- 验收：Service 并发/锁/旧预览/恢复/回放/断库/响应丢失；Root HTTP；UI 桌面窄屏、表单保留、原 UUID 核对，无周期读取。只使用 Agent 自有资源并清理。
- 不涵盖外部命令排空、全文件系统回放的独立墓碑、OSS、现场交接或整套 SG-09/11 验收。
