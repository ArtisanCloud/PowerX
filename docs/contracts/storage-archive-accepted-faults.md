# 已接纳归档的传输故障合同

日期：2026-11-09。对应 T158 的一部分；不关闭 T155、整个 T158、SG-09 或 SG-11。

## 身份与结果

- 请求键经摘要写入归档任务清单；同一策略和请求键重放返回原任务。已知任务的重试使用原 Job ID，增加 attempts，不新建归档任务。
- `status=success` 只表示本地采集完成。只有远端对象及指定版本清单完整读回、校验通过，并通过当前控制链检查后，才记录 `remote_state=success`。
- 对象或清单 PUT 的响应丢失时，远端可能已有内容。`remote_state=failed` 表示本次传输未完成验证，不能解释为“远端什么也没写”。本地副本、源日志和原任务继续保留。
- 同一任务重试可复用完整读回并校验过的内容寻址对象。清单确认丢失后可能在同一键产生新清单版本，不能宣称“远端没有任何重复版本”。

## 当前权威与清理

- 凭据被目标拒绝，或正式控制事务在远端已接收对象后失去数据库连接，均不能凭部分写入生成远端成功记录。
- `VerifyLifecycleFile` 只接受已成功完成远端传输的任务，并重新读取源文件和远端完整内容。历史成功徽标不直接授予当前删除资格。
- 本轮故障测试不调用源删除或远端过期删除；断言故障后的源文件和本地内容 SHA256 保留、清理握手返回 false、没有新增远端 DELETE。修复目标后显式重试原任务，再验证完整读取握手。
- 正式调度器已有同任务、有次数上限和退避的传输重试；这与页面周期查询不同。本轮自有测试不启动调度器，通过原 Job ID 显式恢复，未改变生产重试策略。

## 页面

“存储治理 → 日志归档与追溯 → 检索与取回”分别显示本地采集结果、远端结果及任务编号。远端未确认时提示可能已有部分内容；本地已采集内容仍可通过既有下载入口重新校验。未知状态不得显示成功。

元数据读取失败和 SSE 断线保留已有任务、错误及搜索草稿；推送事件、重连同步和手动刷新读取元数据，无变更时不周期查询，也不自动提交归档写请求。离开页面释放连接。
