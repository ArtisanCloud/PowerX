# 调用日志期限策略的数据库权威

2026-11-07。属于 SG-11 的两张调用日志表切片；系统表专项规则、联合恢复与生产交付仍按 [T166～T174](../../specs/027-monitor-center/tasks.md#us9-commercial-gates) 跟踪。[隔离验收记录](evidence/database-retention-control-validation-20261107.json) 不代表日常或线上已经接管。

## 范围与唯一写入口

只管理 `capability_registry_invocation_traces` 与 `capability_registry_event_publications`，实际 schema 使用本实例正式模型配置。固定适配器限制已登记且未删除租户、记录分类、终态时间和关联保护，不接收表名、SQL、任意过滤条件。业务事件、未知租户、无法核验来源和仍需保留的引用不会因为记录较老而直接删除。`adopt_legacy` 仅允许核验同租户、终态链路、主题和负载相符的旧通知，先隔离；不重试业务操作，也不把进入事件通道称为业务送达成功。

普通策略存入现有 `ops_storage_control_configurations` 的 `database-retention` 域。CAS、不可变配置版本、Root 操作者、UUID 原请求回执与正式 TaskBus 持久登记同事务提交。旧 `PUT /database-retention` 返回 428；源码不再读取旧 JSON 来执行清理或覆盖配置。策略更新不会更改 PostgreSQL 的 `logging_collector`、`log_statement`，也不执行 TRUNCATE、VACUUM FULL 或手工删除 WAL／数据库文件。

接管保留旧 `database-retention.json`，包括历史结果；有任何 `unconfirmed` 旧结果时拒绝接管，先由运维核验，不以导入新策略掩盖未知删除。接管后自动清理暂停；保存期限也暂停。容量保护 `reject_new_when_full` 独立于清理开关：修改后在发布确认前只收紧，不提前撤销原保护或扩大限额。配置正文和回执不保存连接串、密钥；源指纹为连接标识和固定表身份的摘要，连接／凭据变化后需重新保存并明确开启。

## 执行版本与失效关闭

正式 TaskBus 只发布受控快照，不在消息处理器内删除记录。`database-retention-binding.json` 保存本机 scope、原来源摘要和单调发布水位；`database-retention-control.json` 是只读执行投影。读取和批次使用数据库→主机账本顺序，复用配置 CAS 的锁；核验 scope、当前与已确认版本、不可变版本摘要／操作者／时间、本机投影、水位、来源及旧文件变化。数据库失联、单独回滚、快照丢失或篡改、版本待确认时禁止清理，不回退旧 JSON。

暂停请求一经提交，旧版本预览即失效，批次需等当前版本确认。已经拿到配置锁的有界事务可先完成；停用提交后不会再放行旧版本的新批次。更新过的程序禁止旧方法写策略；**不能阻止仍运行旧二进制的进程**。维护切换必须先停止旧执行器。数据库与主机运维状态一起恢复的完整独立时代次仍属于 T171。

## 预览、执行与回执

预览只读检查业务表，同时在现有 `ops_storage_cleanup_runs` 写入预览凭据；不是“所有数据库都零写入”。账本固定 `tenant_id=0`、`instance_id=db-retention:<scope_hash>`，与文件清理账本隔离，不新增模型或迁移入口。

| 操作 | 约束 |
| --- | --- |
| 预览 | 绑定 Root 操作者、策略版本、固定截止时间和批量上限；有效期 5 分钟 |
| 手动执行 | 必须同时提供原预览 UUID、策略版本、新请求 UUID 和明确确认；同一预览只消费一次 |
| 批次 | 在同一 PostgreSQL 事务内锁当前配置、复核资格、消费预览、变更业务日志行并写完成回执；复用同一连接，无额外借连接 |
| 响应丢失 | GET 原请求回执；404 保持待核对，不重新 POST，不生成新请求冒充重试 |
| 原请求重放 | 相同操作者、版本、预览和触发类型才返回原回执；不同载荷返回 409，不再次执行 |
| 后台周期 | 继续使用 PowerX 既有调度；仅当前已确认且开启的策略可运行，每周期最多 100 批／60 秒，每批最多 1000，且受原有迁移和部署开关限制 |

预览数量是当时的有界候选量，不是锁定待删主键清单。执行使用原预览截止时间，重新核验分类、租户、终态、引用和行锁，实际数量可以减少。通知超时仅转隔离，隔离留存期届满且无引用后才删除。结果回执写失败导致整批回滚；客户端无法确定提交结果时仍需查询原 UUID。

写入批次对固定两张表取得兼容普通写入的 ROW EXCLUSIVE 锁，并在同一事务重检外部引用，防止预检后新增级联外键或删表的 DDL 竞态。每事务限制锁等待 1 秒、SQL 8 秒；服务入口总时限 10 秒。完成回执和过期预览只在同域批次内回收：终态保留 30 天，预览到期后最多分批清 500 条，域账本达到 200000 条时停止新增，不能丢弃未知结果换取继续清理。没有后台清理活动时，过期元数据可暂留。配置历史版本保持原有独立控制合同。

DELETE 使记录空间可被 PostgreSQL 重用，不保证立刻增加文件系统可用空间；容量保护持续使用物理关系占用及整盘预留。普通 VACUUM 可按数据库维护安排执行，不由该界面承诺压缩整个库。

## Root UI 和验证步骤

1. 先在授权维护窗口完成既有集中迁移和执行器准备；缺索引或存在外部引用时页面说明阻塞，不在运行时补建索引。
2. 进入「监控中心 → 存储治理 → 数据库期限」，查看空间、迁移／部署门禁、已保存／执行确认／本机配置三个版本。
3. 显式接管并确认。自动清理保持暂停，旧文件与历史回执保留。
4. 弹层配置期限、批次与独立容量保护；保存后等待 SSE 确认。表单保留原 CAS，外部更新不覆盖草稿；冲突后可明确放弃草稿并载入最新版本。
5. 单独确认开启自动清理。手动检查本批候选，再使用该预览执行；查看记录中的版本、数量和触发来源。
6. 若响应丢失，界面锁定写入并保留弹层，只核对原请求。没有回执时先停留核验，不反复点执行。
7. 页面通过初次读取、手动刷新、SSE 变更和断线重连同步；无常驻详情轮询。分区切换保留表单，身份切换由原工作区销毁组件并释放连接。

新接口见[专用 OpenAPI](../../specs/027-monitor-center/contracts/database-retention-control.openapi.yaml)。仅平台 Root 人类访问会话，API Key、插件／STS 和服务身份均不授予整机维护权限；无委托服务 capability。
