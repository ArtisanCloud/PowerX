# 专项系统表期限策略接管

2026-11-07。属于 SG-11 的两类固定适配器切片；[验收证据](evidence/system-table-retention-control-validation-20261107.json)来自自有 PostgreSQL、正式 HTTP／TaskBus／SSE 和本地 Nuxt，不代表日常或生产已经接管。全部交付门槛仍看 [T166～T174](../../specs/027-monitor-center/tasks.md#us9-commercial-gates)。

## 已批准范围

| 固定标识 | 允许进入候选的条件 | 保留的记录 |
| --- | --- | --- |
| `capability_registry_health_probe_results` | 已过保留期的 healthy／unhealthy／degraded；探测时间和更新时间均过期；重试时间不在未来；同适配器存在更新且未删除的探测 | 最新探测、未知状态、空适配器、未来重试、近期更新 |
| `capability_registry_discovery_cache` | 明确软删除；删除、过期、签发、更新时间均超过宽限；租户仍登记且未删除 | 当前缓存，即使已过期仍保留供陈旧回退；有效缓存、近期退休和未知租户 |

期限为 7～3650 天，每批 1～500 行。规则不开放表名、时间列、SQL 或任意过滤谓词。TaskBus 去重、调度状态、审计、RBAC 和业务表不因展示在系统清单就获得删除许可。本切片不修改 PostgreSQL 日志配置，不执行 TRUNCATE、VACUUM FULL 或删除 WAL／数据库文件。

## 每类策略独立管理

每个适配器使用 `system-table-retention.<fixed_adapter_sha256_first32>` 控制域。域识别仅接受上述两个固定标识对应的值，不接受任意哈希通配。复用 `ops_storage_control_configurations`／`ops_storage_control_revisions` 的 CAS、不可变 Root 操作者／UUID 请求回执及同事务正式 TaskBus 登记，不新增策略表或运行时迁移。

两类表拥有独立版本、发布确认、来源证明、预览和运行账本。一类修改或尚待发布，不作废另一类的预览；旧共享 JSON 的另一类记录变化也不作废本类的来源证明。每类的旧来源摘要包括其原规则、历史运行和预览；旧文件不覆盖。有本类未确认历史结果时禁止接管，不能用新策略隐藏未知删除。

接管和保存期限均暂停本类清理；开启／暂停是独立、明确确认的变更。旧 PUT 保存入口返回 428。新版 standalone 服务没有数据库控制权威时不能继续通过旧 JSON 删除；旧二进制不受新源码约束，部署交接仍须停止它们。

`system-retention-probe-binding.json`／`system-retention-discovery-binding.json` 分别保存 scope、来源摘要和单调发布水位，对应 `*-control.json` 是只读投影。执行时在配置锁内检查数据库当前／确认版本、不可变审计、投影摘要／操作者／时间、水位、安装归属和来源指纹。数据库故障、单独回滚、文件篡改／丢失或旧来源变化时停止清理，不回退旧设置。连接标识仅保存摘要，数据库／凭据变化后需重新保存并确认。

`configuration.ready` 表示允许配置写入的控制执行器条件；`configuration.execution_ready` 表示当前版本已确认、来源匹配，不代表清理已开启。状态的 `ready` 还要求本表字段、有效索引、外部引用、治理账本和部署门禁就绪。控制消费者退出时拒绝配置写入；已批准策略的有界执行仍逐批核对数据库，不能仅凭本地快照离线删除。统一紧急停用、完整恢复时代次等总门槛不由本切片关闭。

## 批次与原请求核对

预览不更新或删除源表记录，但会在现有 `ops_storage_cleanup_runs` 保存五分钟凭据。运行命名空间固定为 `sys-retention:<scope_hash>:<fixed_adapter_id>`，`tenant_id=0`；不能跨表消费预览或冒用回执。

同一 PostgreSQL 事务完成：锁定本表策略 → 核验当前确认版本 → 校验原操作者／预览／期限 → 消费一次预览 → 再检查固定规则并删除有界候选 → 保存完成回执。复用同一连接，连接池仅一个连接也可完成。回执写入失败则整批回滚，预览不被错误消费。

源表适配器继续采用 SKIP LOCKED；写批次取得兼容普通写的 ROW EXCLUSIVE 锁，并在该事务重检外部引用，阻止预检后新增级联外键的竞态。候选数仅是预览时的有界观测，执行使用相同截止时间并重新检查当前状态，不能把预览当作冻结主键清单。

结果不确定时，只 GET 原 UUID。404 仍保持待核对，不自动重放 POST；原请求相同才回原结果，不同版本／预览／操作者返回冲突。执行回执在控制权威当前读取失败时仍可独立查询。终态回执保留至少 30 天；过期预览及已消费凭据有界回收，每次最多 500 条；每类账本达到 200000 条时停止新增，不丢弃未知证据。

后台沿用 PowerX 原有生命周期调度。每次周期每类最多 5 批，总周期有 15 秒上限，每批服务时限 10 秒，适配器 SQL 上限 2 秒、锁等待 500 毫秒。未接管、暂停和待发布视为暂停，不当成清理失败；状态损坏等异常仍报告失败。调用日志治理同样先判断接管／暂停资格，避免没有启用的策略污染统一清理健康状态。

## Root 页面使用

1. 授权维护窗口先完成现有集中迁移和索引准备；页面不自行补建索引。
2. 进入「存储治理 → 系统表清单」，搜索上述表，点击「配置清理」。详情使用容量、历史、安全清理分区。
3. 「安全清理」内再按策略配置、预览执行、运行记录分区；核心规则、实际状态和三个版本始终可见。只展示当前任务，窄屏采用分区选择器。
4. 勾选明确确认后接管本表规则。自动清理保持暂停；另一类表继续独立管理。
5. 编辑期限和批次，保存并暂停；等待 SSE 执行确认，再单独确认启用。草稿保持原 CAS，外部更新不覆盖输入；冲突后可明确放弃草稿并载入最新版本。
6. 切到预览执行，检查候选、截止时间后明确确认一批。未知结果锁定写入及父弹层关闭，显示原 UUID；切换分区仍有返回任务和核对入口。
7. 运行记录展示数量、策略版本、触发方式和请求编号。删除行不等于立刻释放磁盘空间。

初次读取、手动刷新和 SSE 事件／重连同步允许读接口；无常驻详情轮询。身份切换和离开页面释放旧组件连接。新 API 见[专项 OpenAPI](../../specs/027-monitor-center/contracts/system-table-retention-control.openapi.yaml)。只接受平台 Root 人类访问会话，服务身份、插件／STS、API Key 均不能获得整机维护权限。

## 交付边界

本切片未迁移日常库、未重启用户服务、未接管／清理生产数据。旧执行器交接、联合数据库／运维状态恢复时代次、自动恢复演练、外部密钥提供器、SG-09 双环境及 7／14 天长期证据继续待办。本地受控时钟推进两个周期，不等价于连续十五分钟或长期运行验收。
