# 归档策略的数据库权威与执行保护

2026-11-06，SG-11 归档策略切片。目标配置继续遵循[目标控制合同](archive-target-control.md)，凭据值继续保存在[独立加密提供器](archive-credential-vault.md)。本合同记录源码和隔离验收，不代表正式站已升级或 SG-11 全部完成。

## 页面和操作顺序

“存储治理 → 日志归档与追溯 → 归档策略”与“备份中心 → 媒体与日志 → 高级配置”使用同一编辑器；后者按媒体来源过滤，内部仍分“归档策略／存储目标”。旧媒体页的 JSON 策略／SSH 目标写表单已移除。按需媒体导出仍为单次操作，不会创建或启用计划。

1. 查看旧目录的策略数量与摘要，Root 明确确认“暂停并接管策略”。接管保留原文件及全部旧值作为来源证据；每条策略版本加一，归档与远端清理都设为关闭。
2. 保存草稿只包含来源、目标、频率、本地副本规则、远端保留天数、份数／容量预算和媒体配套数据库选项。编辑已有策略也会暂停两个执行开关，页面在保存前明确说明。
3. 查看“已保存／已生效／执行端快照”，等待正式 TaskBus 发布确认。保存与发布不是同一个状态。
4. 日志的远端归档必须先通过当前 S3 目标的执行端验证，再单独确认开启；远端到期治理另行确认。确认固定当前策略列表版本、单条策略版本、目标版本与验证指纹，事件刷新不能悄悄替换确认基准。
5. 目标、凭据或来源变化后，即使配置开关仍显示开启，执行状态也会明确提示未满足条件，不再允许执行。验证目标不会自动复活策略；可先暂停，再明确确认开启。
6. “暂停全部执行”同时关闭归档和远端清理，不依赖目标可连接或验证有效。单独关闭其中一项时，另一项若保持开启，仍必须满足其执行条件。
7. 版本冲突保留原草稿与基准，只在用户选择“放弃此草稿，载入最新策略”后重建。载入失败也不丢草稿。结果未知时禁止再次提交，只 GET 原 UUID 回执；404 继续视为未确认，不授权重发。

桌面纵向分区、390px 选择器、编辑与确认弹层保持同一份上下文。后台状态来自既有备份 SSE，包含配置发布和文件账本变更；不新增常驻状态轮询。旧后端或未迁移控制面只读，不回退文件保存。

## 范围、字段和保留语义

- 平台 tenant 0，固定 domain `archive-policies`，安装范围为 `(host_id, filesystem_id, instance_id)`。最多128条策略；列表 CAS 与各策略独立 revision 同时检查。新策略 UUID 等于创建请求 UUID。
- 每项保存固定 `PolicySettings`、开关、登记来源指纹、服务端产生的目标版本／验证指纹、创建时间。来源指纹绑定部署登记的目录、轮转、活动文件、属主及数据连接身份；DSN／凭据只在内存参与摘要，不写数据库正文。
- 频率1～525600分钟；本地／远端天数1～3650；份数1～10000；容量预算0～2^50字节。0表示未设置远端预算，S3归档或远端治理启用前必须大于0；UI以GiB编辑、按字节保存。
- 远端容量和份数是写入预算，到达后停止新归档，不会为了腾空间缩短保留天数。远端到期清理按天数、具体版本和引用保护判定。
- 本地副本超出份数或天数时才进入候选；最新、受保护、运行中、未确认状态及未成功归档的远端副本保留。暂停策略引用的对象也不会被另一策略的全局缓存回收删掉。
- 更换目标命名空间后，旧归档保持历史记录，不会被新目标的清理任务误标过期。目标证明版本变化后的旧本地副本保守保留，后续需要专项迁移／核对，不能承诺马上释放这部分空间。

日志启用要求已验证的S3目标。媒体计划可以选择“仅本地”，不需要远端目标或远端预算；远端治理必须另选已验证S3。配套数据库快照仍受既有来源配置约束，本轮没有真实业务数据库恢复验收。SSH目标元数据和历史取回保留，但受控远端策略暂不激活SSH；继续使用SSH需另完成带版本守卫的执行合同，不能把本切片作为SSH生产替换证明。

## 数据、发布和兼容

复用 `ops_storage_control_configurations` 与 `ops_storage_control_revisions`，无新表。CAS、不可变请求回执、操作者／Trace和正式 TaskBus 登记同事务提交；重复请求须匹配同一操作者、动作、参数与原始版本。查询同时返回原操作版本和当前发布状态，不重放写入。

`archive-policy-control.json` 位于预算私有目录，是原子写入、fsync的执行投影，不是配置权威。读取核对scope、数据库确认版本、不可变版本及正文摘要。首次投影即使已被更高版本替代，也核对最初接管来源。数据库、表、身份或快照不明时阻止执行；不提供离线批准期限，不从旧 `policies/*.json` 恢复执行开关。

集中迁移仍由正式 storage governance 入口挂载，构造函数不迁移、不自动接管。Core启动绑定目标与策略控制面并运行原调度器。私有 `policy-control-binding.json` 和运行配置 `policy_control_required:true` 阻止新版独立 worker 绕回旧 JSON；旧二进制及临时任务的正式交接仍属于 T171，不能双跑。

## 执行边界与暂停

任务准入、每次S3对象写入／清单发布、本地副本保留以及远端到期回收均核对数据库权威。任务准入也受版本锁保护，不能拿暂停前读到的对象创建暂停后的新计划执行。

配置及运行时按策略域→目标域固定顺序在同一SQL事务内锁定，目标与策略都不变时才进入S3动作；单连接池不再因嵌套借连接阻塞。配置发布与预算账本遵守DB→主机账本顺序。长任务的来源互斥锁为非阻塞租约，发布不取得该锁，避免等待环。目标／策略投影的只读核验遇到主机账本瞬时占锁时最多等待500毫秒；配置投影发布同样只在尚未进入持久化回调时等待锁，回调开始后不在此重做。配置提交、远端写入和删除均不自动重放。超时、损坏和身份不明仍停止执行，不使用旧缓存替代权威。归档任务保留安全控制错误码，不输出外部存储原始错误或凭据。

执行保护使用最长15秒的上下文：单次S3写入、一次远端清理批次或本地清理按边界运行，超时不继续下一项。暂停可能等待当前批次退出后提交，不承诺撤回已发出的远端请求。暂停提交后新的准入／远端动作不能继续使用旧版本。此前已准入的本地只读采集可以收尾，远端写入仍需重新过守卫。

已产生删除意图或部分完成但结果不明时保留 `unconfirmed` 和具体版本记录，不能伪报完成。`expiry_pending`、保护项及暂停策略的缓存引用保留。HTTP或单次Tick的上下文结束后，副本保留改用有界服务上下文运行；仍重新检查当前权威，避免请求取消导致长期不执行保留规则。

本地对象删除仅针对归档派生缓存，不删除登记的源日志、媒体业务文件或数据库表。现有文件日志自动治理是另一份明确配置，不能用归档策略代替其删除授权。

## API 合同

统一前缀下 `/admin/ops/backup/archives`，旧 `/admin/backup` 别名共享Root守卫：

| 方法／路径 | 请求或结果 |
| --- | --- |
| GET `/policy-configuration` | 权威、版本、来源摘要、期望策略列表 |
| POST `/policy-configuration/adoptions` | `request_id, legacy_digest, confirm:true` |
| POST `/policies`，`action:save` | `request_id, expected_revision, expected_policy_revision, policy_id, settings`，两个开关由服务器设为关闭 |
| POST `/policies`，`action:status` | 同一版本信封，`enabled, remote_cleanup_enabled, confirm:true, expected_target_revision, expected_target_fingerprint`，不接收settings |
| GET `/policy-configuration/requests/:request_id` | 原操作者只读核对不可变回执 |

新建 `policy_id:""`、单条期望版本0；更新／状态操作明确UUID和单条版本。暂停全部、本地媒体无远端目标时，目标期望版本／指纹可为0／空。旧完整 `Policy` 原样POST返回400；内部旧 `SavePolicy` 在绑定后返回428。不存在通用JSON编辑、任意命令或HTTP代理入口。

只有真实平台Root用户access session可访问；匿名、普通用户、API Key、STS均拒绝。新路由明确忽略为 `root_runtime_control`，不发布租户／插件能力，也不新增服务grant。400为动作／字段错误，409为版本、来源、目标或启用条件变化，422为目标未验证／来源未就绪，428为未接管，503为控制面不明；503或丢失响应不能证明未提交。详见[OpenAPI](../../specs/027-monitor-center/contracts/archive-policy-control.openapi.yaml)。

## 验收、升级和剩余门槛

[隔离验收记录](evidence/archive-policy-control-validation-20261106.json)分别记录原生PostgreSQL、正式TaskBus驱动配合miniredis、真实HTTP/JWT/SSE、S3版本协议仿真、原生文件回收和真实浏览器。协议仿真不是长期私有OSS/S3提供商或正式部署验收。

升级时先准备可信host／filesystem／instance身份、集中迁移和TaskBus，再由Root明确接管。旧文件发生漂移先核对，不自动覆盖；失败或未知版本保留数据。回退前需停止新旧执行器并在授权维护窗口核对两份状态，不能通过删除绑定文件或手改JSON回退。

主机预算、备份／系统快照等域的数据库接管、DB＋投影＋绑定＋密钥联合恢复时代次、旧执行器部署交接、外部KMS、真实云端取回和SG-09的7／14天验证继续待办。特别是整套历史数据库与运行账本同时回滚的防复活门槛尚未完成，不能据此关闭商用发布门槛。

代码：`archive_ops/policy_control.go` 管理固定DTO、运行钩子与绑定；`storage_governance/archive_policy_control.go` 管理数据库与双域事务锁；`control_repo.go` 的 `WithCurrentTx` 复用当前事务；共享UI为 `ArchiveGovernanceBody.vue`、`ArchivePolicyControlStatus.vue`，媒体页复用该编辑器。
