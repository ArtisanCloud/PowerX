# 专家知识库结构化方法论

## 1. 结论

PowerX 不应为每个行业或岗位从零设计一套知识库结构。正确策略是：

```text
通用知识工程骨架 + 职位智能体来源快照 + 行业扩展 + 企业自定义扩展
```

通用骨架保证检索、审核、版本、图谱和 Agent 运行的统一性。职位智能体来源快照和行业扩展提供专业语义，解决财经、营销、运营等场景差异。产品界面上仍然展示为“智能体”和“知识结构”，不要求用户管理模板包。

## 2. 通用知识对象

所有领域都可以归一到以下知识对象：

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| Source | 原始来源 | 录音、图片、文档、会议纪要、网页 |
| Observation | 事实或观察 | 某客户转化率下降 |
| Concept | 概念 | 私域增长、现金流周期 |
| Principle | 原则 | 高客单价产品先建立信任再转化 |
| Method | 方法论 | 三层定价分析法 |
| SOP | 操作流程 | 每周经营复盘流程 |
| Case | 案例 | 某项目增长复盘 |
| Decision Rule | 决策规则 | 当库存周转低于阈值时触发补货审核 |
| Template | 模板 | 预算分析表、营销 Campaign brief |
| FAQ | 常见问题 | 客户异议处理问答 |
| Evidence | 引用证据 | 数据、截图、原文、录音片段 |

## 3. 知识层级

推荐统一分为五层：

1. 原始材料层：保存原始文件、来源、上传人、时间。
2. 事实观察层：抽取可验证事实、事件、数据和引用。
3. 概念方法层：沉淀概念、原则、方法论、模型。
4. 流程规则层：沉淀 SOP、决策规则、检查清单。
5. 应用输出层：沉淀模板、案例、FAQ、可复用方案。

## 4. 职位智能体知识结构示例

### 4.1 营销智能体

扩展结构：

- 战略层：品牌定位、目标客群、市场机会、竞争格局。
- 策略层：渠道策略、内容策略、转化策略、预算策略。
- 执行层：Campaign SOP、素材模板、投放检查清单。
- 复盘层：指标解释、失败案例、优化建议。

### 4.2 财务智能体

扩展结构：

- 报表层：资产负债表、利润表、现金流表解读。
- 预算层：预算模板、预算偏差规则。
- 风控层：异常指标、审批规则、风险案例。
- 经营分析层：毛利、现金周期、费用结构、预测模型。

### 4.3 运营智能体

扩展结构：

- 流程层：标准作业流程、跨部门协作流程。
- 指标层：效率、质量、成本、交付周期。
- 异常层：异常分类、处理规则、升级机制。
- 复盘层：事故复盘、优化动作、经验沉淀。

### 4.4 CEO/经营管理智能体

扩展结构：

- 战略层：目标、竞争、组织能力、关键约束。
- 经营层：收入、成本、利润、现金流、增长引擎。
- 组织层：团队结构、关键岗位、管理机制。
- 决策层：重大决策记录、判断原则、风险偏好。

## 5. 行业扩展示例

行业扩展只扩展专业分类、术语、合规要求和标准流程，不重新定义底层知识对象。

示例：

- 金融：产品合规、风险评级、客户适当性、投研框架。
- 零售：门店运营、会员增长、库存周转、促销活动。
- 制造：BOM、工艺流程、质量控制、设备维护。
- 教育：课程体系、学员画像、教学评估、转化路径。
- 医疗：诊疗规范、合规审查、患者教育、质量控制。

## 6. 入库规则

1. 原始材料必须先入 Source，不得只保留摘要。
2. 自动抽取结果必须先进入 draft。
3. Method、SOP、Decision Rule 必须经过人工审核。
4. Evidence 必须保留可追溯引用。
5. 同一知识对象可绑定多个标签和分类，但只能属于一个 owner scope。
6. 重要知识更新必须生成新版本，不覆盖旧版本。

## 7. 检索与 Agent 使用

Agent 检索时应优先使用结构化意图：

- 要方案：优先 Method、SOP、Template、Case。
- 要解释：优先 Concept、Principle、Evidence。
- 要决策：优先 Decision Rule、Case、Evidence。
- 要复盘：优先 Observation、Case、SOP、Metric。

这样可以避免所有内容都被当作普通 chunk 平铺检索。
