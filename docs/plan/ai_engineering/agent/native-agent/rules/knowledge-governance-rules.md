# 原生智能体知识治理规则

## 1. 写入原则

原生智能体不得把专家上传材料直接写入正式知识库。所有自动处理结果必须先进入 draft/staging。

标准链路：

```text
source -> parsed -> structured draft -> review -> approved -> published
```

## 2. 归属规则

Knowledge Space 必须有明确 owner scope：

- `user`：个人数字分身知识库。
- `department`：部门方法论和 SOP。
- `tenant`：公司级公共知识。
- `project`：项目知识。
- `customer`：客户上下文知识。

Agent 访问 Knowledge Space 必须通过显式绑定，不允许按名称或岗位自动推断。

## 3. 审核规则

以下内容必须人工审核后才能发布：

- Method 方法论。
- SOP 流程。
- Decision Rule 决策规则。
- 合规、财务、法务相关知识。
- 覆盖旧版本的重要知识。

低风险内容可以配置为批量审核，但仍必须保留来源和版本。

## 4. 版本规则

正式知识发布必须生成版本。

禁止直接覆盖：

- 方法论。
- SOP。
- 决策规则。
- 合规知识。
- 已被引用的知识卡片。

替换旧内容时，旧版本进入 `superseded`，保留回滚引用。

## 5. 冲突处理

当新知识与已有知识冲突时：

1. 不自动覆盖。
2. 生成 conflict draft。
3. 标明冲突对象、冲突字段、来源材料。
4. 交由 owner 或管理员确认。

## 6. 共享规则

个人知识库默认不共享。部门知识库可按角色共享。公司知识库可按租户策略共享。

从个人知识库提升到部门知识库必须经过审核，并记录贡献者和来源。
