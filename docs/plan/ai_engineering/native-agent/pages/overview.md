# 原生智能体页面总览

## 1. 页面总入口

复用 Web Admin 现有 AI 设置菜单，用户侧入口保持为“智能体”和“智能团”。不要新增独立的“智能体模板包管理”一级页面。

页面目标：

1. 展示 PowerX 内置智能体、租户自建智能体、插件智能体和外部导入智能体。
2. 支持租户启用、复制、配置和绑定知识库。
3. 支持查看每个智能体的 Skill、Workflow、Knowledge Space、权限和运行状态。
4. 支持克隆内置/已有智能体、从零创建、从插件市场导入三种创建路径。

## 2. 页面文档

本目录把页面设计拆成独立文档，避免一个页面总览承载过多细节。

| 页面 | 文档 | 作用 |
| --- | --- | --- |
| 智能体管理：模板/克隆视图 | `native-agent-directory.md` | 在智能体管理中查看可克隆的内置智能体、插件智能体和租户已有智能体 |
| 智能体管理：运行实例视图 | `tenant-agent-instances.md` | 管理租户实际运行的 AgentInstance |
| 创建智能体向导 | `agent-create-wizard.md` | 支持克隆智能体、从零创建和插件导入 |
| 专家知识库工作台 | `knowledge-curator-workbench.md` | 采集、结构化、审核和发布知识 |

## 3. 依赖页面

以下页面依赖 Workflow runtime、Skill Pack 管理和 Agent 运行审计。知识库迭代能力上线前，这些依赖必须真实可用，不能用隐藏的替代流程绕过。

### 3.1 Workflow Pack 页面

路径建议：

`/settings/ai/workflow-packs`

用途：管理原生智能体可用的业务流程模板。

页面需要：

- Workflow Pack 列表
- 节点图预览
- 版本管理
- 发布/归档
- 使用中的 Agent 列表

### 3.2 Skill Pack 页面

路径建议：

`/settings/ai/skill-packs`

用途：把多个 Skill 组织成面向岗位或行业的能力包。

页面能力：

- Skill Pack 列表
- 关联 Skill 明细
- 使用中的 Agent
- 版本与来源
- 可见租户/角色

## 4. 全局交互原则

1. 用户面对的是“智能体、智能团、知识库、草稿、审核、发布”，不是底层 capability id 或 template id。
2. 所有选择器必须可搜索，列表必须分页。
3. 智能体来源、行业扩展和职位类型使用业务名称展示，技术 key 只在调试区、审计区或 API 合同中展示。
4. 原生智能体启用过程必须有预检：Skill、Knowledge Space、权限、Workflow runtime。
5. 知识库发布必须二次确认，并显示来源和变更摘要。
6. 智能体模板包只作为来源快照、版本快照、克隆预览和审计信息出现，不作为用户独立维护对象。
