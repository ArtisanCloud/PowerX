# PowerX 分割策略（人话版）

> 这份文档专门解释“分页/字数/分段模式/分隔符”怎么一起工作。  
> 如果 UI 或实现有争议，以这里为准。

---

## 1. 先说结论（最常见的问题）

1) **顺序 = 你在“切分优先级”里拖的顺序（仅分页/字数/分隔符）**  
   分段模式不参与排序；系统会按规则把它自动插入到顺序里。

2) **“分段模式”只决定“怎么切”**  
   不是顺序，也不是最终长度，只是“切块边界怎么找”。

3) **“字数策略”是长度兜底**  
   `target` 会合并短段，`cap` 只切超长段。

4) **“分页优先”只在有页信息时生效**  
   有页码就先按页分桶；没页码就当没选。

---

## 2. 四块配置到底是啥（对应页面上的四块）

### 2.1 分页优先（page）
- 作用：**先按页分桶**，不跨页合并。
- 触发条件：**文档有分页信息才生效**（PDF、OCR、带页信息的格式）。

### 2.2 字数策略（size）
- `target`：把短段先合起来，再切到接近目标长度（默认通用）。
- `cap`：只对超长段下刀，不做合并（保守）。

### 2.3 分段模式（segment）
- 这是“切块边界怎么找”的规则（见第 4 节）。
- 只决定边界，不决定顺序。

### 2.4 分隔符（separator）
- 先在自然边界切（空行/句号/分号等），再进入窗口切。
- 更像“温柔版断句”。

---

## 3. 执行顺序（你拖的顺序）

默认顺序（分段模式开启、且非 `unit`）：

```
分页（page） → 分段模式（segment） → 字数策略（size） → 分隔符（separator）
```

**当分段模式 = `unit` 时，默认顺序会变成：**

```
分页（page） → 字数策略（size） → 分段模式（segment） → 分隔符（separator）
```

你可以拖拽改顺序（只影响分页/字数/分隔符），  
后台会把“分段模式”按规则插回顺序里执行。  
被你关闭的步骤会跳过，不会参与。

常见组合建议：

- **普通文档（SOP/说明书）**  
  `page → size(target) → segment(unit) → separator`

- **对话/工单**  
  `segment(conversation) → size(cap)`  
  先按轮次，再用 `cap` 防止超长。

- **表格/台账**  
  `segment(table_row) → size(cap)`  
  行优先，分隔符一般关掉。

- **合同/条款**  
  `segment(clause) → size(cap)`  
  条款优先，长度兜底。

---

## 4. 分段模式（segmentMode）解释（先把“语义”讲清楚）

**先把“语义”说透：**

- **规则语义**：用标点/句子边界/换行等规则切句。  
  不调用大模型，不做“理解”，只是规则拆分。
- **智能语义（LLM）**：用大语言模型判断“语义段落边界”。  
  会调用 LLM 读懂上下文后决定哪里切。

**当前规范：**  
UI 里的 `semantic` = **规则语义**。  
**智能语义（LLM）**作为独立能力，由“语义方式”配置面板启用。

| 模式 | 人话解释 | 适合 |
|---|---|---|
| `unit` | 按长度窗口切（默认） | 普通长文 |
| `heading` | 按标题/段落结构切 | 手册/规范 |
| `semantic` | 规则语义：按句子边界切（非 LLM） | 论文/报告 |
| `clause` | 按条款编号切 | 合同/制度 |
| `table_row` | 按表格行切 | 表格/台账 |
| `code_block` | 按代码块切 | 代码/配置 |
| `conversation` | 按对话轮次切 | 工单/聊天 |

**你问的重点**：  
如果选了 `conversation`，`size` 还有用吗？  
答：有用，但只是“兜底”。先按轮次切，太长才继续切。

> 说明：  
> `semantic` 当前对应**规则语义切句**（规则拆分）。  
> 智能语义（LLM）通过独立配置面板启用与生效。

> 特别说明（避免误解）：  
> `unit` **不是分页**。  
> `unit` 表示“按长度窗口切分”，与是否有页信息无关。  
> “分页优先”是单独的开关：只有文档有页信息时才会先按页分桶。

---

## 5. “分页/字数/分隔符”的逻辑关系（更直白）

- **分页**：先分桶，不跨页。  
- **分段模式**：在桶里找边界。  
- **分隔符**：让边界更自然。  
- **字数策略**：最后控制长度。

如果你想“先结构再长度”，开启分段模式即可；  
顺序只影响分页/字数/分隔符，分段模式由系统自动插入。

---

## 6. 智能语义（LLM）切块（功能说明）

> 这部分是功能说明：描述能力形态、配置项与调用链路。

当需要“智能语义边界”（LLM）时，使用一个**独立配置面板**（类似知识图谱的独立配置）：

### 6.1 UI 结构（与分段模式联动）

- 当 `segmentMode=semantic` 时，显示“语义方式”子面板  
- 语义方式选项：**规则语义 / 智能语义（LLM）**  
- 选择“智能语义（LLM）”后，展开完整配置

### 6.2 配置项（面板字段）

- **开关**：启用/关闭 LLM 语义切块  
- **模型**：使用 PowerX 系统当前环境的 LLM 设定（Active LLM profile）  
- **提示词**：语义边界识别 prompt（可选默认模板）  
- **最大长度**：每段最大 token/字符限制  
- **回退策略**：LLM 失败则回退到规则切句
- **超时**：单段超时与整文档超时  
- **批量大小**：每次送入 LLM 的段数上限  
- **输出锚点**：语义分段编号（segment_part）、摘要/主题（可选）

### 6.3 调用链路

> 调用方式（功能链路）：  
> Ingestion 阶段 → 智能语义切块模块 → PowerX LLM 路由（Active LLM profile）。  
> 建议走统一的 LLM Gateway/Router（与 Agent/Chat 使用同一套鉴权与限流）。

### 6.4 输出与落库

- `segment_part`：语义段序号  
- `semantic_summary`：可选摘要  
- `semantic_topic`：可选主题标签  
- `semantic_confidence`：置信度（可选）

---

## 7. 命名建议（避免误解）

为了避免把“规则切句”误解为“LLM 理解”，建议 UI 文案区分：

- **语义（规则）**：按句子边界切  
- **语义（智能）**：LLM 判断语义边界（独立配置面板）

---

## 8. 支持范围与实现对齐（别担心，代码对齐）

分段模式的**支持值**来自接口层校验（oneof）：

- `backend/internal/transport/http/admin/knowledge_space/dto.go`

分段/分页/分隔符/窗口切块的**实现**在：

- `backend/internal/service/knowledge_space/chunking.go`

这两个地方和 UI 的选项是对齐的，不是拍脑袋。
