# 存储治理商用交付约束

基线：2026-11-05，更新：2026-11-07。本文定义商用交付约束，不代表已完成迁移、权限调整或生产交付。正式任务及唯一进度来源为 [US9／SG-11](../../../specs/027-monitor-center/tasks.md#us9-commercial-gates)。

## 1. 完成标准

存储治理属于整机、全库运维能力。可编辑页面和局部测试通过只构成阶段成果；配置权威、发布与执行状态、并发保护、授权、凭据、升级恢复及长期运行证据均通过后，才能声明商用交付完成。原 SG-09 的真实远端取回、7 天运行与 14 天样本要求继续有效。

源码已收口整机备份 HTTP 新旧路径及旧 gRPC Root 边界，并新增统一配置事务／TaskBus 发布基础模块，详见[实现合同与当前边界](../../contracts/storage-control-authority.md)。系统表容量监控与[逐来源文件日志保留](../../contracts/storage-file-lifecycle-control.md)已接入；[归档目标](../../contracts/archive-target-control.md)已接入显式接管、数据库版本、TaskBus 投影、独立验证及 Root UI；[归档策略](../../contracts/archive-policy-control.md)也已接入暂停式接管、显式启用、源／目标守卫和媒体共用UI；[主机预算](../../contracts/storage-host-budget-control.md)已接入保持保护的显式接管、同盘唯一归属和最终准入守卫；[数据库备份计划](../../contracts/database-backup-policy-control.md)已复用现有计划表接入原子版本、暂停式接管、逐次作业／清理守卫和共享 UI；[系统快照计划](../../contracts/snapshot-policy-control.md)已接入数据库权威、暂停式接管、采集版本及原子隔离清理；旧独立协调器自动计划受限；[两张调用日志表期限](../../contracts/database-retention-control.md)已接入暂停式接管、同事务预览／批次／回执与独立容量保护，[两类专项系统表期限](../../contracts/system-table-retention-control.md)已接入独立版本、暂停式接管、同事务批次和分区 UI。[归档凭据文件提供器](../../contracts/archive-credential-vault.md)已实现独立加密、接管、轮换和吊销切片，外部 KMS、旧历史对象处置及完整恢复时代次尚未完成。尚未覆盖所有配置域、旧二进制交接、联合恢复时代次及外部密钥提供器，整套 SG-11 仍未关闭。本轮未重启日常 Core、未迁移日常数据库；下文描述目标约束，不能作为已上线事实。

## 2. 权威与持久化

| 内容 | 唯一权威 | 执行端持久化与边界 |
| --- | --- | --- |
| 平台保留策略、归档目标元数据、备份／快照计划、用户可编辑预算 | 平台数据库中的正式配置与版本 | 本地只使用经发布并核对的版本快照，禁止与数据库各自接受独立配置写入 |
| 主机最小启动信息、身份、执行所有权、租约、运行意图和结果、紧急停用 | 独立的受保护运维状态 | 数据库不可用时仍能保护数据及完成已授权的维护恢复；不是另一套普通策略编辑入口 |
| S3 等凭据 | 独立的受控密钥存储 | 平台配置仅保存引用和版本；文件落盘需加密及密钥分离，不能把文件权限视为加密 |

平台配置必须明确 platform／host／filesystem／installation／resource 范围，不能把当前实例数据库中的一条预算冒充跨实例主机唯一执行权威。同盘协调和最终空间准入继续服从唯一主机协调者。

数据库中的策略版本、修改审计和待发布意图在同一事务提交。版本发布复用正式 TaskBus／事件合同，采用幂等处理和持久确认，不另建私有轮询队列。执行快照至少绑定协议版本、配置版本与摘要、安装及执行节点、资源范围、目标验证和凭据引用版本；通过原子替换发布。

## 3. 保存、生效与并发

- UI 分别显示编辑草稿、已保存待发布、已发布待执行端确认、已生效、发布失败和结果待核对；同时显示期望版本与执行端实际版本。保存成功不等于执行端已使用新值。
- 创建需要持久幂等键及请求摘要；重复请求返回同一结果，重复键配不同载荷明确冲突。修改、启停及切换当前计划必须执行数据库原子版本条件更新。前端预读比对不能替代后端条件更新。
- 当前／默认计划的唯一性、版本递增、操作审计和发布意图必须在同一事务中完成。旧客户端缺少必需条件时明确报错，不采用隐式覆盖。
- 响应不明时只读回核对原操作，不自动再次创建、启用或执行。未知状态不能显示成功、删除 0 项或已暂停。
- 紧急停用优先于缓存快照和待发布版本；已在提交中的操作仍需如实核对结果，不能用停用标志伪装撤销成功。执行器使用版本／所有权约束阻止旧实例继续发起新批次。
- 数据库不可用时禁止发布新启用配置。已批准快照能否继续执行，必须按资源类型明确允许范围、失效时间和保护校验；未知、过期、身份变化或证明不完整时阻止破坏性操作。恢复进度遵守现有独立维护执行器与限时票据合同。

## 4. 平台权限与凭据

当前阶段整机／全库配置、计划、启停和清理接口统一要求真实平台 Root 用户会话，包括原数据库备份接口及其旧路径别名；前端隐藏菜单不能代替后端授权。普通租户管理员、租户 RBAC 授权、API Key 和 STS 不能获得这些整机权限。

未来如增加平台运维角色，应单独设计平台范围的查看、编辑、发布、启停、取回、删除权限；不能沿用租户权限开放全库操作。如确需服务调用，应另行声明最小权限的正式 typed `core_internal` 合同，不能借用 Admin 权限或任意代理。

凭据需具备受控写入、版本、轮换、吊销与迁移流程。密钥不进入普通配置导出、日志、URL、浏览器持久存储或数据库配置正文；凭据或目标变化必须使旧验证证明失效。密钥服务或密钥不可用时明确阻塞依赖操作。

## 5. 升级、迁移与恢复

1. 先对旧数据库及 JSON 配置执行只读盘点，记录身份、版本、摘要、启用值和实际执行器；提供 dry-run 差异与备份清单。
2. 新权威导入保留原始值及来源证据，默认待接管；不能因升级自动启用清理、归档或直接删除，也不能悄悄停止仍由旧执行器负责的任务。UI 如实显示旧执行器仍在运行。
3. 在明确维护与接管步骤中冻结旧写入口，核对执行所有权，再切换新发布链路；不允许两套配置写入者或清理执行器同时成为权威。失败保留可核对状态和回退版本。
4. 恢复清单覆盖平台配置数据库、必要运维账本、程序与插件、媒体、归档引用及独立密钥恢复方式。数据库历史记录不能覆盖较新的运行结果或紧急停用状态。
5. 恢复或跨主机迁移后重新核对实例、文件系统、执行所有权、凭据与目标验证。历史数据库中的启用值不能自动触发新环境清理；未核对前保持待确认。

## 6. 发布验收

| 门槛 | 必须取得的证据 |
| --- | --- |
| 权威与版本 | 同资源两个并发更新只有一个成功；重复创建不产生第二条；切换当前计划没有双默认或半提交 |
| 生效一致性 | 数据库已保存但发布失败时 UI 不显示已生效；重启后可核对同一版本；停用不会被旧消息或旧快照覆盖 |
| 授权 | 对真实路由及旧别名验证匿名、普通用户、带租户备份权限用户、API Key、STS 均不能管理整机；合法 Root 按操作范围通过 |
| 安全与恢复 | 密钥不明文导出；断库、断网、发布中断、目标变化、磁盘满和恢复旧数据库均不触发未知删除或重复执行 |
| 产品流程 | 桌面及窄屏就地配置、失败反馈、输入保留、事件重连、身份切换与无周期状态查询均有实际请求证据 |
| 真实运行 | 独立测试资源的保存、发布、生效、启停、升级回滚和恢复闭环；原 SG-09 的双环境及长期运行证据不能用单测替代 |

本地页面及配置接入已有阶段证据，不能据此勾选上述商用门槛。不得为取得证据修改客户或生产策略、删除业务数据，迁移与重启遵守项目既有授权边界。


## 7. 2026-11-07 执行保护切片

当前源码加入[安装级受控执行保护](../../contracts/storage-execution-control.md)及[操作手册](../../guides/deploy/027-monitor-center/usecase-us9-storage-execution.md)：Root 紧急暂停无需等待配置消费者；交接保持锁定、核对已登记策略暂停／发布，完成后仍需单独恢复。原子锁覆盖有界受控步骤，已接纳长任务和外部旧进程不由该开关终止；运维声明不能替代现场证明。首次前明确显示 unmanaged，不在启动时自动修改策略。

本轮隔离验收不关闭上面的商用门槛。联合数据库／运行元数据恢复时代次、旧二进制与真实脚本移交、外部密钥治理、自动恢复演练及双环境长期目标继续待办；未迁移或操作日常／生产。
