## 1. 问题与目标

数据库保存业务记录和媒体引用，媒体存储保存文件内容；配置、插件绑定与程序版本还会影响应用能否启动。独立任务执行时间不同，选择较新的数据库和较旧的媒体可能出现文件缺失。即使两个任务同时启动，也不能据此证明它们属于同一个业务状态。

目标是让管理员只选择一个系统快照，由系统协调采集、校验、导出和覆盖目标实例。底层允许数据库 dump、媒体增量对象、配置密文分别保存，用户不负责配对。

| 能力 | 现有实现 | 本次目标 |
|---|---|---|
| 数据库备份 | 完整逻辑 dump；不包含外部文件与配置 | 作为统一快照的必需组件 |
| 媒体归档 | 本地媒体和登记的 S3 对象；可选同 MVCC 配套 dump | 必须关联数据库、引用清单及文件内容版本 |
| 配置与版本 | 未纳入媒体配套归档 | 保存必要配置、绑定、版本和受保护的密钥材料 |
| 恢复 | 新数据库副本、新媒体目录；分开查询状态 | 一次确认后保护当前状态、覆盖固定实例并验证；独立页面在业务停机时仍可访问 |
| 导出／导入 | 媒体包可下载；数据库副本入口接收 `.dump` | 可独立导出、跨实例导入的完整系统恢复包 |
| 正式生效 | 运维维护窗口手动切换 | 同一恢复任务自动完成保护、覆盖、验证及业务启动；返回恢复前状态时再恢复保护快照 |

现有操作说明继续见 [备份中心手册](../../guides/deploy/027-monitor-center/guide.md)、[媒体归档](../../guides/deploy/027-monitor-center/usecase-us6-media-archives.md)、[数据库恢复副本合同](../../contracts/restore-copies.md)。

## 2. 快照边界与内容

每个快照有独立 `snapshot_id`，表示一个经过一致性检查的应用恢复点。记录业务时间点、采集起止时间和时区；时间标签不承诺任意时间点恢复，也不等于文件扫描结束时间。首版以整实例为范围，包含该实例的所有租户和插件；目录中的租户标识不代表租户级数据子集。

| 组件 | 必须保存或声明的内容 |
|---|---|
| 数据库 | Core 与插件 schema 的结构和数据、数据库版本、扩展、迁移版本、媒体引用所用事务快照标识 |
| 媒体 | 有效原图／附件／变体的引用清单、驱动、相对 key、大小、SHA256 与实际内容；不可只存生产 URL |
| 配置 | 实际生效配置及其来源、必要环境变量、插件 registry／host-values／数据库绑定；使用允许清单，不递归打包整个部署目录 |
| 密钥材料 | 解密备份数据和应用加密字段所必需的材料或可解析的密钥引用；与普通清单分离、加密保存 |
| 程序版本 | Core／Web Admin 的配套版本、插件 ID／版本、包摘要与目标平台、迁移兼容性及可取得的安装产物 |
| 外部依赖 | PostgreSQL 扩展、Redis／队列等依赖的用途、恢复方式，以及是否存在尚未覆盖的持久业务状态 |

所有必需组件齐全才允许成为“完整系统快照”。仅数据库、仅媒体和旧媒体配套 dump 保持原类型，不自动升级为系统快照。

首版以当前 PostgreSQL + 本地媒体部署为验收基线。S3／OSS、独立插件库或其他持久业务存储若没有受支持的采集与恢复适配，必须报告不支持并阻止宣称整站可恢复；不能静默遗漏。日志、缓存、会话令牌、临时上传、构建缓存和备份目录本身默认不纳入业务恢复内容。待执行的队列／事件不能当作缓存静默丢弃或重新发送，需在外部依赖清单中明确处置方式。

云盘／整机快照另行保护操作系统与整盘部署环境，不替代本计划的业务一致性与跨环境恢复验收。云侧快照是否启用、是否完成，必须独立核实。

## 3. 采集与一致性

日常手动和定时快照在线采集，不暂停 Core、插件或业务写入。数据库 dump 与已就绪媒体引用共享 MVCC，配置及程序做身份与摘要校验。在线包不包含与数据库同一恢复点的 Redis 队列，必须标记实际范围，不能把 `ready` 称为已通过生产整站恢复验收。

具备明确维护边界和依赖合同的完整包才能进入生产整站恢复。恢复前保护快照在停止全部受管写入者后采集，包含冻结数据库、媒体、配置、程序和独占 Redis 的持久点；失败则停止覆盖。现有在线包只允许显式的本地业务数据演练，不自动升级为生产恢复点。

媒体读取期间发生删除、覆盖、大小或摘要变化，配置和程序身份发生变化，或发现未适配外部依赖时，必须失败或明确阻断。MVCC 不自动冻结文件系统、对象存储或 Redis；多个组件拥有相同时间标签不能证明它们一致。

## 4. 统一清单、保存与保留

以下为完整目标逻辑模型；实际文件／DTO 以 `snapshot_ops/types.go` 和 [API 合同](../../contracts/system-snapshots.openapi.yaml)为准，不能将目标字段当成现有字段：

| 清单部分 | 内容 |
|---|---|
| 标识 | `contract_version`、`snapshot_id`、源实例／部署身份、逻辑恢复时间、采集窗口、触发方式 |
| 范围 | 必需组件、已排除内容、外部依赖及不支持项 |
| 数据库 | 组件 ID、内容摘要／大小、数据库／扩展／迁移版本、事务快照标识 |
| 媒体 | 引用清单、对象摘要、大小、内容版本、原驱动及 key；不依赖仍有效的生产访问链接 |
| 配置／程序 | 非敏感配置摘要、密文引用、加密版本／密钥定位信息、Core／插件版本与产物摘要 |
| 验证 | 完整性、组件一致性、依赖检查结果；业务演练报告独立关联 |

快照执行状态为 `queued → capturing → verifying → ready`，失败和中断是终态。`ready` 表示必需内容齐全且完整性通过，**不等于完整业务已验收**。本地可用、异地复制完成、完整包导出完成、恢复演练通过分别记录，不能合并为一个 success。

- 元数据、任务日志和恢复账本保存在被恢复业务库之外的稳定运维位置；持久化合同以 `snapshot_ops`、`system_recovery` 及私有 profile 为准。
- 媒体可以复用现有 CAS 对象，但必须先让旧清理器识别系统快照引用并持锁保护；适配完成前独立保存对象，不能只新增引用后继续让旧 GC 删除内容。
- 保留策略按整份系统快照执行，保留最新完整恢复点及显式保护项。底层对象只有在所有快照／恢复／导出任务都不再引用后才能删除。
- 调度展示真实间隔和下一次执行时间；保存时校验保留窗口与频率，不能依赖“每日备份”等自由名称解释周期。一次父任务执行全部必需组件。
- 密钥不得仅存在于被备份数据库或故障服务器。完整导出包应使用独立提供的解密材料，离开源实例仍能验证和解密；不得把明文密钥写入清单、日志或下载名称。

## 5. 完整恢复包与跨环境导入

导出必须物化 manifest 引用的全部必需内容：数据库、媒体对象、配置密文及必需版本产物。内部可以增量去重，但下载包不能依赖另一个未随包提供的增量链、本机 CAS 目录、源实例的数据库或生产 URL。

若支持按版本引用安装包，必须在导出完成前解析并核验产物；不能把仍需访问生产目录才能取得的程序称为独立完整包。不同平台产物必须明确声明可用性；Linux 二进制不能直接当作 macOS 可执行程序。

导入先检查格式版本、完整性、解密材料、路径安全、空间、程序／PostgreSQL／扩展兼容性和目标平台。未知版本、越界路径、软链接逃逸、缺内容、错误密钥和不支持驱动均拒绝进入恢复阶段。

| 目标模式 | 环境处理 |
|---|---|
| 同一实例正式恢复 | 保留已确认的实例身份；按快照核对数据库角色、插件绑定、加密材料和程序版本，在维护窗口统一切换 |
| 本地／开发恢复测试 | 新数据库、新媒体根目录、新端口与目标域名；显式映射配置和凭据，避免连接生产服务 |

跨环境复制必须遵守[插件数据库环境隔离](plugin-database-isolation.md)：设置目标 `deployment.env`，制定可审计的绑定／角色／schema 迁移计划，不直接复制生产绑定或只替换连接字符串。目标环境的权限与密钥映射未完成时不启动插件。

恢复测试模式必须在 Core／插件／worker 启动之前禁止业务定时任务、事件／队列消费、Webhook／支付回调发送和其他外部业务写入；同时阻止目标连接指向生产库、生产媒体或生产队列。后台隔离不等于只把前端端口改掉。恢复所需的身份与权限使用专门的目标环境映射，生产会话令牌不作为测试登录凭据。

## 6. 恢复当前实例与异机验证（2026-10-18 收敛）

恢复表示覆盖目标实例。用户不管理长期候选环境，不执行单独切换或切回。异机验证在另一台干净 PowerX 目标上导入完整包并恢复，生产实例不变。

管理员流程：**选择快照 → 明确确认覆盖 → 自动预检查 → 维护停写 → 保护当前状态 → 覆盖并验证 → 恢复完成**。

1. 使用唯一私有登记的受管目标，固定实例 ID、正式配置路径、PG 数据目录、DSN 和入口。HTTP 不接受路径、连接串、环境或程序命令。
2. 在临时目录做包与应用预检查，不改变当前站；校验结束清理，不创建长期运行环境。
3. 停止全部受管写入者，保存并保护此刻完整快照 B；保存失败绝不覆盖。
4. 数据库、媒体、配置和程序统一替换为 A。内部暂存仅用于失败补偿，不展示为环境。
5. 正式配置原子落盘到固定路径。正常启动、重启及后续备份始终使用当前实例；活动账本只记录维护状态和代次，不可指向另一套实例。
6. 验证数据库、媒体、Core、插件及正常运行；完成后删除旧暂存目录，只保留 B 的保护快照。
7. 恢复写入前失败或进程中断时按独立账本补偿；写入可能恢复后保持维护，不自动舍弃新数据。
8. 用户需要 B 时选择 B 的保护快照再次恢复，不进行环境切换，不合并数据。

独立协调器、只读限时 SSE 票据、任务账本及中断恢复继续保留。旧切换/回退/环境清理 API 返回 410；历史任务保留审计，不能作为新恢复验收结果。

现有未接入的外部 PostgreSQL、Redis 和任意安装目录继续拒绝覆盖；生产必须先完成受管部署接入，不得仅删除 dev 检查绕过目标归属。具体操作及已知限制以[恢复手册](../../guides/deploy/027-monitor-center/usecase-us8-managed-recovery.md)为准。

## 7. 页面与权限

- `/ops/backup` 的目标主入口是“系统快照”：首先展示最近完整恢复点、实际定时周期、可恢复状态、异地状态和最近演练结果。
- 主要操作为创建快照、恢复、导出、导入；快照详情用弹层／抽屉按“组件、验证、执行记录”分块，路径、SHA256、错误和 Trace 按需展开。
- 原数据库／媒体／日志功能保留为组件维护及高级操作，明确标注范围。仅数据库任务不得占用“最近整站备份成功”的展示位置。
- 恢复任务聚合数据库、媒体、配置、应用验证及覆盖状态；媒体复制完成而数据库仍在恢复时，父任务不得显示恢复成功。
- 首版整站快照导出、导入、恢复和切换仅允许平台 Root 用户 JWT，拒绝普通租户、STS 和插件 API Key。保持既有组件 API 的授权边界，不扩大权限。
- 已冻结 Root 运维 [typed API](../../contracts/system-snapshots.openapi.yaml)，不接入租户／插件能力目录；已增加独立协调器的 Root 恢复与切换 API，部署后方可用于线上。客户端不能提交任意 shell、SQL、DSN 或服务器路径。

## 8. 实施拆分与兼容

1. 合同与清单：类型、状态、组件范围、加密／密钥、版本、目标映射和持久化账本。
2. 统一采集：父任务调度、一致性边界、数据库与媒体复用、配置／版本采集、整套保留与 GC。
3. 独立导出／导入：完整包、解密与完整性预检查、跨平台版本产物解析。
4. 异机恢复验证：目标身份／凭据映射、禁止外部业务写入、数据库／媒体／应用联合报告。
5. 覆盖恢复：固定正式配置、保护快照、独立协调器、失败补偿和中断恢复。
6. 页面与验收：统一主入口、组件高级操作、两轮验收及失败演练。

旧策略、dump 和媒体归档继续可用；不自动停用、不改周期、不改已登记状态。用户显式采用系统快照策略后再调整重复调度。历史产物若要纳入统一模型，必须显式校验和补齐全部组件，不按时间临近自动拼接为完整快照。

本期不承诺任意时刻 PITR、整机重装、自动云盘快照管理、任意历史版本迁移、生产对象存储原地覆盖或外部业务系统回滚。无法满足所选目标时明确阻断。

## 9. 验收与交付门槛

详见 [US8 系统快照两轮验收](../../guides/deploy/027-monitor-center/usecase-us8-system-snapshot-acceptance.md)。

- 第一轮本地：状态 A 包含可辨识业务记录和媒体；采集快照后形成状态 B；导出 A 并恢复到独立目标，证明记录、文件、绑定与版本属于 A，源 B 保留。另在自建测试实例验证覆盖恢复、正常重启、保护快照恢复和失败补偿。
- 第二轮部署后：先通过本地验收，再由运维升级；观察真实定时任务至少一个计划周期，可按一天验收；把自动快照完整包带到本地／独立开发实例，断开源实例依赖后恢复并验证。
- 等一天验证的是调度、部署与真实数据链路，不是恢复技术必须等待一天。不能将手动任务或测试时钟冒充真实定时任务。
- 缺媒体、错误摘要、缺配置／密钥、版本不兼容、磁盘不足、并发变更、重复提交、进程中断、切换失败都需明确失败／阻断及可检查的后续状态。
- 记录快照／恢复任务 ID、源／目标版本与模式、组件数量与摘要结论、业务检查、源环境未改变证明、切换／回退结果及 RTO；报告不包含生产凭据或业务敏感正文。
- 构建通过、HTTP 202、dump 可解析、文件复制成功均不能单独替代完整业务恢复验收。
